------------------------------------------------------------
0. 全体の流れ
------------------------------------------------------------

■ タイトル画面に置いているもの（TitleScene::Init で、この順番に追加）

  順番  オブジェクト       役割                         描くもの
  1     Ground            地面（ゲームと同じ）          3D
  2     Sky               空（ゲームと同じ）            3D
  3     CathedralRuins    廃墟（ゲームと同じ）          3D
  4     TitleChara        攻撃を見せ続けるキャラ        3D
  5     TitleCamera       動き続けるカメラ              なし（カメラ）
  6     TitleEmber        舞い上がる火の粉              2D
  7     TitleUI           ロゴ・メニュー・フェードなど  2D

  2Dは「後から追加したものほど手前」に描かれる。
  なので、火の粉はロゴやメニューより後ろに見える。

■ 1フレームの流れ

  Update()       … キャラのアニメーションを進める、火の粉を動かす、メニューの入力を見る
  PostUpdate()   … キャラの地面判定、カメラの位置を決める
  PreDraw()      … カメラの行列をシェーダーに渡す
  Draw()         … 3Dの描画（空・地面・廃墟・キャラ）
  DrawSprite()   … 2Dの描画（火の粉 → ロゴ・メニューなど）


------------------------------------------------------------
1. TitleScene（タイトル画面そのもの）
------------------------------------------------------------

■ Init()：画面を作る

  CreateObject<Ground>();
  CreateObject<Sky>();
  CreateObject<CathedralRuins>();
  std::shared_ptr<TitleChara> chara = CreateObject<TitleChara>();
  std::shared_ptr<TitleCamera> camera = CreateObject<TitleCamera>();
  camera->SetChara(chara);                                          … カメラにキャラを教える
  KdEffekseerManager::GetInstance().SetCamera(camera->GetCamera()); … エフェクト用のカメラ
  CreateObject<TitleEmber>();
  m_wpUI = CreateObject<TitleUI>();

  ・CreateObject<T>() は「作る → Init()を呼ぶ → リストに追加」をまとめた関数（GameSceneと同じ作り）
  ・Effekseerのエフェクトは、どのカメラから見るかを教えないと正しく表示されないので、
    タイトル用カメラを登録している
  ・TitleUI は後でメニューの結果を聞くので、m_wpUI に覚えておく

■ Event()：メニューの結果を見て画面を切り替える

  switch (ui->GetResult())
  {
  case TitleUI::Result::Start: SceneManager::Instance().SetNextScene(SceneType::Game); break;
  case TitleUI::Result::Exit:  Application::Instance().End(); break;
  }

  ・TitleUI は、メニューで決定したあと「フェードアウトが終わってから」結果を返す
  ・そのため、画面が真っ暗になった瞬間にゲーム画面へ切り替わる（または終了する）


------------------------------------------------------------
2. TitleChara（攻撃を見せ続けるキャラ）
------------------------------------------------------------

  BaseChara を継承している。
  アニメーション・重力・地面判定は、Player と同じ仕組みをそのまま使う。

■ ① 読み込むもの（Init）

  ・モデル：SK_Assassin.gltf（Playerと同じもの）
  ・アニメーション：
      Combat_Idle（武器を構えた待機）
      攻撃タイプ 1・3・5 の 1～4段目（12本。名前は Attack_1_1 ～ Attack_5_4）
    ファイルの場所は Player の CreateAnimList() と同じ決まりで組み立てている。
  ・タイプ2は空中技、タイプ4は溜め攻撃（3分割）なので、タイトルで見せるのには
    向かないと考えて外した。

■ ② 演技の台本を作る（CreateShowcase）

  最初に「何をどの順番で再生するか」をリストにしている。

    [0]  Combat_Idle（150フレーム ≒ 2.5秒）
    [1]  Attack_1_1
    [2]  Attack_1_2
    [3]  Attack_1_3
    [4]  Attack_1_4
    [5]  Combat_Idle（150フレーム）
    [6]  Attack_3_1 … [9] Attack_3_4
    [10] Combat_Idle（150フレーム）
    [11] Attack_5_1 … [14] Attack_5_4
    → [0] に戻ってずっと繰り返す

  1つ分の情報は ShowcaseStep という構造体にまとめている。
    animName    … 再生するアニメーション名
    attackType  … 攻撃の種類（待機なら0）
    attackStep  … 何段目か
    holdFrame   … 待機を続けるフレーム数（攻撃は0 ＝ アニメーションの最後まで）

■ ③ 次の演技を始める（StartStep）

  m_stepIndex = index % m_showcase.size();   … 最後まで行ったら0に戻る
  m_stepTimer = 0;
  m_isEffectPlayed = false;
  ChangeAnimation(step.animName, isLoop, true, kAnimBlendFrame);

  ・「% m_showcase.size()」で、最後の次は最初に戻る。これで無限ループになる
  ・待機はループ再生、攻撃は1回だけ再生
  ・kAnimBlendFrame = 6 で、前のアニメーションから6フレームかけてなめらかにつながる

■ ④ 毎フレームの判断（UpdateShowcase）

  待機中の場合
    ・m_stepTimer を1ずつ増やし、150になったら次へ進む

  攻撃中の場合
    1. 斬撃エフェクト
       アニメーションが10フレーム目（kSlashEffectFrame）を過ぎたら、1回だけエフェクトを出す。
       m_isEffectPlayed で「もう出したか」を覚えている。
    2. 次の段へ進むタイミング
       ・1～3段目は、25フレーム目（kComboCancelFrame）で次の段へ移る。
         最後まで待たずにつなぐので、連続攻撃に見える
       ・4段目（最後）は、アニメーションの最後まで再生する
       ・アニメーションが読み込めていない場合は、止まらないようにすぐ次へ進む

■ ⑤ 斬撃エフェクトの位置（PlaySlashEffect）

  Math::Matrix rot = CreateRotationY(m_angle);          … キャラの向き
  forward = rot で (0,0,1) を回したもの                  … キャラの正面方向
  pos = 足元 + 正面 × 1.0 + 上 × 1.0                     … 前に1m、高さ1m
  EffectPlayer::Play(エフェクト名, 拡大 × 回転 × 移動);

  ・ゲーム中の PlayerStateComboAttack と同じ位置・大きさにしている
  ・エフェクト名は GetSlashEffectName() で選ぶ
      タイプ1      … 段ごとに _Sword1-1 ～ _Sword1-4
      タイプ5の4段目 … _Sword5-4
      それ以外     … _Sword1

■ ⑥ 更新（Update）

  UpdateShowcase();      … 演技を進める
  BaseChara::Update();   … アニメーションを進める・重力
  UpdateWorldMatrix();   … 描画用の行列を作る

  ・BaseChara::Update() は、ルートボーン（root）の移動を毎フレーム0に戻している。
    そのため、攻撃で前に踏み込むアニメーションでも、キャラはその場から動かない
  ・地面判定（GroundHit）は BaseChara::PostUpdate() がそのまま行うので、地面の上に立つ

■ ⑦ 向きと描画

  ・m_angle = 180 … キャラは -Z方向（カメラのいる方）を向く
  ・モデル自体が逆向きに作られているので、Playerと同じく m_angle + 180度 回して描く
  ・DrawLit() では、Playerと同じ設定（裏面も描く・半透明合成）で DrawModel している。
    剣はモデルに含まれているので、一緒に描かれる
  ・GetLookAtPos() は「足元 + 高さ1.1m（胸のあたり）」を返す。カメラはここを見る

3. TitleCamera（動き続けるカメラ）
------------------------------------------------------------

  CameraBase を継承している。PostUpdate() で毎フレーム位置を計算する。

■ ① カメラの位置は「角度・距離・高さ」の3つで決める

  キャラの胸（lookAt）を中心に考える。
    yaw       … キャラの正面から、左右にどれだけ回り込むか（角度）
    distance  … キャラからどれだけ離れるか
    height    … 胸の高さからどれだけ上にいるか

■ ② 揺れ続ける動き（sinを使う）

  yaw      = 28度 × sin(フレーム × 0.0045)
  distance = 3.4 + 0.35 × sin(フレーム × 0.0031)
  height   = 0.25 + 0.2 × sin(フレーム × 0.0057)

  ・sin は -1 ～ +1 の間を行ったり来たりする関数。
    かける数（0.0045など）が小さいほど、ゆっくり動く
  ・3つの速さをわざとバラバラにしている。
    動きの組み合わせがなかなか同じにならず、「同じ動きの繰り返し」に見えにくくなる
  ・一周にかかる時間：角度 約23秒、距離 約34秒、高さ 約18秒

■ ③ 登場演出（最初の3秒）

  intro    = EaseOutCubic(フレーム / 180);    … 0 → 1 に変化（最後はゆっくり）
  yaw      = lerp(-50度, ②のyaw,      intro);
  distance = lerp(7.5,   ②のdistance, intro);
  height   = lerp(2.5,   ②のheight,   intro);

  ・lerp(A, B, t) は「AとBの間の、tの割合の位置」を返す（t=0ならA、t=1ならB）
  ・最初は「斜め左・遠く・高い位置」にいて、3秒かけて②の動きに合流する
  ・EaseOutCubic によって、最初は速く、最後はふわっと止まるように寄っていく
  ・180フレーム以降は intro = 1 のままなので、②の動きだけになる

■ ④ 角度などから実際の座標を求める

  dir = (sin(yaw), 0, -cos(yaw));     … yaw=0 のとき (0,0,-1) ＝ キャラの正面
  eye = lookAt + dir × distance + (0, height, 0);

  キャラは -Z を向いているので、カメラも -Z 側に置いて正面から映す。

■ ⑤ キャラを画面の右寄りに映す

  forward = lookAt - eye;              … カメラの向き
  right   = Up × forward（外積）;       … カメラから見た右方向
  target  = lookAt - right × 0.9;      … 見る点を左へ0.9mずらす

  カメラが「キャラより少し左の点」を見るので、キャラは画面の右側に映る。
  空いた左側にロゴとメニューを置いている。

■ ⑥ カメラの行列を作る

  view = XMMatrixLookAtLH(eye, target, Up);   … eye から target を見るビュー行列
  m_mWorld = view.Invert();                    … 逆行列 ＝ カメラのワールド行列

  ・このフレームワークは左手座標系（LH）
  ・Math::Matrix::CreateLookAt は右手系用なので使わず、DirectX の XMMatrixLookAtLH を使う
  ・作った m_mWorld は、CameraBase::PreDraw() がシェーダーに渡す

4. TitleEmber（舞い上がる火の粉）
------------------------------------------------------------

  2Dで描く粒。粒は2種類ある。

    種類               数     大きさ        速さ                          明るさ
    火の粉 m_embers    70個   6～18px      上へ0.6～1.8px/フレーム        1.0
    光の玉 m_bokehs    10個   120～300px   ほぼ止まっている（ゆっくり漂う）0.12（とても薄い）

  色はオレンジ (1.0, 0.55, 0.2) と、剣の軌跡と同じ青 (0.3, 0.7, 1.0)。
  火の粉は25%が青になる。

■ ① 粒1つが持つ情報（Particle）

  pos            … 位置（画面の中央が(0,0)、右が+X、上が+Y）
  velocity       … 1フレームに動く量
  color          … 色
  size           … 大きさ
  swayPhase      … 左右に揺れるタイミングのずれ（粒ごとにバラバラ）
  swayWidth      … 左右に揺れる幅
  life / maxLife … 残りの寿命 / 最初の寿命（フレーム）

■ ② 粒を作る（SpawnEmber / SpawnBokeh）

  ・位置・速さ・大きさ・寿命などは、すべて KdRandom でランダムに決める
  ・最初の1回（isFirst = true）：画面全体にばらまく。
    寿命もランダムな途中から始めるので、起動した瞬間から画面中に火の粉がある
  ・2回目以降：画面の下の外側（40px下）から出す

■ ③ 動かす（UpdateParticle）

  p.pos += p.velocity;                                          … 上へ移動
  p.pos.x += sin(フレーム × 0.02 + p.swayPhase) × p.swayWidth;  … 左右にゆらゆら
  p.life--;                                                     … 寿命を減らす

  寿命が0になるか、画面の上の外へ出たら、②で作り直して下から出し直す。
  これでずっと途切れずに舞い上がり続ける。

■ ④ ふわっと出てふわっと消える（CalcFade）

  fadeIn  = 生まれてからのフレーム ÷ 60   （0→1、最大1）
  fadeOut = 残りの寿命 ÷ 60              （1→0、最大1）
  明るさ  = fadeIn × fadeOut

  生まれてから1秒かけて明るくなり、消える前の1秒で暗くなる。
  突然パッと出たり消えたりしない。

■ ⑤ ちらちら瞬く・描く（DrawParticles / DrawSprite）

  flicker = 0.75 + 0.25 × sin(フレーム × 0.2 + 粒ごとのずれ);  … 0.5～1.0で細かく揺れる
  color.w = フェード × flicker × 明るさ;
  DrawTex(光の玉の画像, x, y, size, size, nullptr, &color);

  描く前に ChangeBlendState(KdBlendState::Add) で「加算合成」にしている。
  ・加算合成：「下の色 + 描く色」で、重なるほど明るくなる描き方。光や炎の表現によく使う
  ・光の玉の画像は、中心が明るく外側が黒（黒は足しても変わらない）。
    そのため、四角い画像なのに丸く光って見える


------------------------------------------------------------
5. TitleUI（ロゴ・メニュー・画面の演出）
------------------------------------------------------------

  一番大きいクラス。「状態」「入力」「時間に合わせた演出」「描画」に分けて説明する。

■ ① 初期化（Init）

  1. 画像を作る（SpriteUtil を使う）
       m_glowTex      … 光の玉（64×64）
       m_vignetteTex  … 四隅を暗くする画像（128×72）

  2. 文字を作る（UIText）
       ・ロゴ「BRAVER」（特大フォント、Times New Roman、150px）
       ・サブタイトル「- DUAL BLADE ACTION -」
       ・メニュー「START」「CONTROLS」「EXIT」
       ・操作案内の文字2種類（メニュー用・操作説明用）
       ・操作説明の文字（タイトル＋8行）
     文字の画像はここで1回だけ作り、毎フレームは描くだけにしている（毎回作ると重いため）。

  3. 操作説明の行（AddControlsRow）
       ・UIText は文字の「中心」の位置を指定する仕組み
       ・操作説明は左揃えにしたいので、「左端の位置 + 文字の幅の半分」を中心として指定する
       ・キーの列（青、左端 x=-300）と、動作の列（白、左端 x=-40）の2列

■ ② 状態（State）

  画面は4つの状態を切り替えて動く。

    Intro（登場演出中）
      │ 185フレーム経過 または Enter
      ▼
    Select（メニュー選択中） ◀─────────────────┐
      │ START / EXIT を決定       CONTROLS を決定 │
      │                                  ▼       │ Enter / BackSpace で戻る
      │                           Controls（操作説明）
      ▼
    Decided（決定済み：点滅 → フェードアウト）
      │ 70フレーム経過
      ▼
    m_result に Start / Exit を入れる → TitleScene が画面を切り替える

  状態を変えるときは ChangeState() を使う。
  m_stateFrame（今の状態になってからのフレーム数）を0に戻すため。

■ ③ 入力（UpdateInput）

  bool up      = m_upKey.Update();
  bool upArrow = m_upArrowKey.Update();
  …（9個のキーすべて）
  m_input.up     = up || upArrow;
  m_input.decide = enter || space || click;

  ・KeyTrigger::Update() は「前のフレームは離していて、今押した」ときだけ true を返す。
    押しっぱなしでカーソルが連続で動かないようにするため
  ・Update() は毎フレーム必ず全部呼ぶ必要がある（前のフレームの状態を中で覚えているため）
  ・a.Update() || b.Update() と書くと、a が true のときに b.Update() が呼ばれない
    （C++の「短絡評価」）。そのため、先に全部呼んでから || でまとめている

    上    … W・↑
    下    … S・↓
    決定  … Enter・Space・左クリック
    戻る  … BackSpace・右クリック

  ESCキーは main.cpp で「ゲーム終了」に使われているので、「戻る」には使っていない。

■ ④ 状態ごとの処理

  UpdateIntro
    決定キーで m_frame を登場演出の最後（185）まで飛ばす。これで演出がスキップされる。
    185を超えたら Select へ移る。

  UpdateSelect
    上下キーで m_selectIndex を変える。
    (番号 + 3 - 1) % 3 のように計算するので、一番上で上を押すと一番下へ回り込む。
    決定キーで Decide() を呼ぶ。

  Decide
    CONTROLS なら Controls 状態へ移る。
    START / EXIT なら、選んだ項目を覚えて Decided へ移る。

  UpdateControls
    決定キーか戻るキーで Select に戻る。

  UpdateDecided
    30フレーム点滅 + 40フレームのフェードアウトが終わったら、m_result に結果を入れる。

■ ⑤ なめらかに動く値（UpdateMenuAnimation）

  m_cursorY += (目標 - m_cursorY) × 0.2;

  毎フレーム「目標との差の20%」だけ近づける書き方。
  最初は速く動き、近づくほどゆっくりになって、なめらかに止まる。これを3か所で使っている。

    m_cursorY       … 選んだ項目の高さへ、カーソルの光がスッと移動する
    m_menuScales    … 選んだ項目は1.12倍、それ以外は0.9倍へ、ゆっくり変わる
    m_controlsOpen  … 操作説明を開くと0→1、閉じると1→0

■ ⑥ 時間に合わせた演出（CalcProgress）

  float CalcProgress(int startFrame, int duration)
  { return clamp((m_frame - startFrame) / duration, 0, 1); }

  「startFrame で0、startFrame + duration で1」になる値を返す。
  これを使って、登場演出のタイミングを決めている。

    フレーム    起きること
    0～45      黒からフェードイン
    0～60      上下の黒帯が入ってくる
    30～90     ロゴが大きい状態から縮みながら現れる
    90～125    ロゴが現れきった瞬間に、ロゴの形の光が広がって消える
    80～130    ロゴの下の光の線が、真ん中から左右へ伸びる
    110～150   サブタイトルが現れる
    140～185   メニューが左から滑り込んでくる
    185～      選択できるようになる。ここから下の「ずっと動く演出」が続く

■ ⑦ 描画（DrawSprite）

  奥から順に、次の6つを描く。

  (1) DrawVignette：四隅を暗くする
      四隅ほど黒くなる画像（128×72）を、画面全体（1280×720）に引き伸ばして重ねる。
      中央に目が行き、映画のような雰囲気になる。

  (2) DrawLetterBox：上下の黒帯と操作案内
      ・黒帯の太さは 50px × EaseOutCubic(進み具合)。1秒かけて画面の外から入ってくる
      ・DrawBox で上下に1本ずつ描く
      ・下の黒帯の中に操作案内を表示する
          選択中     … 「W / S : SELECT  ENTER : DECIDE」
          操作説明中 … 「ENTER / BACKSPACE : BACK」
      ・案内の透明度は 0.55 + 0.35 × sin(フレーム × 0.06) で、ゆっくり明滅する

  (3) DrawLogo：ロゴまわり

      【加算合成で描く光】
      1. ロゴの後ろの大きな光
         オレンジの光の玉を 760×300 に引き伸ばして描く。
         明るさは 0.22 + 0.06 × sin で脈打つ。
      2. 光の線
         ・青い光（幅 × 高さ10px）の上に、白い細い光（幅の60% × 高さ4px）を重ねている。
           光の玉の画像を横に引き伸ばしているので、両端がぼやけた線になる
         ・線が伸びきった後は、200フレームごとに、白い光が120フレームかけて
           左端から右端へ走る
         ・走る光の明るさは sin(進み具合 × π)。端では0、真ん中で1になるので、
           ふわっと現れてふわっと消える
      3. ロゴの光
         同じロゴをオレンジ色で、少し大きく（1.02倍 ± 0.01）重ねて描く。
         明るさが sin で脈打つので、ロゴが呼吸するように光る。
      4. 登場の瞬間の光
         ロゴが現れきった後の35フレームだけ、ロゴを1.0倍→1.3倍に広げながら消していく。
         「キラッ」と光る効果。

      【通常の描き方で描くもの】
      5. ロゴ本体
         透明度 = 進み具合、大きさ = lerp(1.35, 1.0, 進み具合)。
         大きい状態から縮みながら現れる。
      6. サブタイトル
         進み具合に合わせてフェードインする。

      文字を描くたびに SetColor と SetScale で色と大きさを変えている。
      そのため、1つの m_logo を使い回して「光」「広がる光」「本体」の3回描いている。

  (4) DrawMenu：メニュー
      ・登場：slideX = -40 × (1 - 進み具合) で、左から40px滑り込む
      ・選択中の項目の後ろの光：青い光を 440×70 に引き伸ばして、m_cursorY の高さに描く
      ・左右の光の点：
          置く位置は「文字の幅の半分 × 拡大率 + 34px + 6 × sin」。
          文字の長さに合わせて離れ、左右にゆらゆら揺れる
      ・項目の文字：選択中は不透明、それ以外は透明度0.45。
          拡大率は⑤の m_menuScales を使う
      ・操作説明を開いているとき：メニュー全体を暗くする（dim = 1 - 0.7 × 開き具合）
      ・決定したとき：(m_stateFrame / 3) % 2 で3フレームごとに点滅させ、後ろの光も強くする

  (5) DrawControls：操作説明
      1. 黒い板：高さが 235 × m_controlsOpen なので、真ん中から上下に開くように見える
      2. 板のふち：上下に青い線を1本ずつ描く
      3. 文字：
           板が開ききる直前（開き具合が0.7を超えてから）、SmoothStep で表示し始める。
           板が小さいうちに文字がはみ出さないようにするため

  (6) DrawFade：黒のフェード
      ・最初：透明度「1 - 進み具合(0～45)」の黒い四角を画面全体に描く。
        だんだん透明になって、画面が見えてくる
      ・決定後：点滅の30フレームが終わってから、40フレームかけて透明度0→1にする。
        真っ暗になる
      ・一番最後に描くので、何よりも手前に表示される


------------------------------------------------------------
6. SpriteUtil（演出用の便利な関数）
------------------------------------------------------------

■ GetScreenSize()

  今のビューポート（描画範囲）の幅と高さを取得する。
  取得できなかったときは 1280×720 を返す。

■ CreateGlowTexture(size)：光の玉の画像

  画像ファイルを使わず、プログラムで1ピクセルずつ色を決めて作っている
  （剣の軌跡の画像と同じ方法）。

    dist   = 中心からの距離（中心0、ふち1）
    bright = SmoothStep(1, 0, dist) の2乗   … 中心ほど明るく、ふちで0
    色 = (bright, bright, bright)、アルファ = 1

  ・加算合成で使うので、明るさは「色」で表している
  ・アルファを1にしている理由：スプライトシェーダーは、画像のアルファが0.1未満の部分を
    描かない（discardする）作りになっているため

■ CreateVignetteTexture(w, h)：四隅を暗くする画像

    dist  = 画面中央からの距離（中央0、上下左右の端1、四隅 約1.4）
    dark  = SmoothStep(0.4, 1.45, dist)   … 0.4より内側は0、四隅に向かって1
    alpha = 0.1 + 0.9 × dark
    色 = 黒

  こちらは「半透明の黒」で暗くする画像なので、アルファで濃さを表している。
  最低値を0.1にしているのは、上と同じ「0.1未満は描かれない」ため。
  0にすると、境目にくっきり線が出てしまう。

■ EaseOutCubic(t)

    1 - (1 - t)³

  t が0→1に変わるとき、最初は速く変化し、最後はゆっくり1に近づく。
  「スッと動いてふわっと止まる」動きになる。
  カメラの寄り、ロゴ、黒帯、メニューなどで使っている。

■ SmoothStep(edge0, edge1, x)

  x が edge0 → edge1 の間で、0 → 1 にS字カーブでなめらかに変化する。
  境目がくっきりしないようにするために使っている。

7. UIText に追加したもの
------------------------------------------------------------

  FontSize::Title … ロゴ用の特大フォント（Times New Roman、150px、4番に登録）
  SetScale()      … 文字の拡大率
  SetAlpha()      … 透明度だけ変える
  GetSize()       … 拡大前の文字列の幅と高さ

■ 拡大の仕組み

  pos = (-幅/2, -高さ/2);                                       … 文字の中心を原点に置く
  SetMatrix(CreateScale(拡大率) * CreateTranslation(中心座標));  … 原点で拡大 → 表示位置へ移動
  DrawFont(...);
  SetMatrix(Identity);                                           … 元に戻す

  ・先に文字の中心を原点に置いてから拡大するので、文字の中心を基準に
    大きくなったり小さくなったりする
  ・最後に Identity（何もしない行列）に戻すのは、他の画像の描画が
    拡大されてしまわないようにするため

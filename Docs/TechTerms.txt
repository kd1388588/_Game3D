 1. ゲームの作りとプログラム（C++）
============================================================

■ ゲームループ（game loop）
  意味　：入力を読む → 動かす → 描く、を 1 秒に何十回も繰り返す、ゲームの心臓部
  BRAVER：1 秒に 60 回。main.cpp が PreUpdate → Update → PostUpdate → Draw を毎フレーム呼ぶ

■ フレーム（frame）／ FPS（frames per second）
  意味　：画面を 1 回描きかえる単位／1 秒に何回描くか
  BRAVER：60 FPS。時間はほとんど「フレーム数」で数える（60 フレーム = 1 秒）

■ シーン（scene）
  意味　：タイトル・ゲーム・ゲームオーバーなど、画面の場面ごとのまとまり
  BRAVER：SceneManager が切り替える。TitleScene / GameScene / GameOverScene / GameClearScene

■ ゲームオブジェクト（game object）
  意味　：画面に出る物（プレイヤー・敵・カメラ・UI など）の共通の形
  BRAVER：KdGameObject。シーンがリストで持ち、毎フレーム Update と Draw を呼ぶ

■ クラス・継承（class / inheritance）
  意味　：データと処理をまとめた設計図／親の設計図を引き継いで、子で付け足す
  BRAVER：BaseChara（親）→ Player・Enemy（子）。BaseGage → HPGage・ATBGage・ATBCommandMenu

■ 仮想関数・override（virtual function）
  意味　：親で決めた関数を、子が自分用に書きかえる仕組み
  BRAVER：Update・DrawLit・DrawSprite などを、オブジェクトごとに override している

■ ステートパターン（state pattern）
  意味　：「待機」「攻撃」「回避」など、状態ごとにクラスを分ける設計
  BRAVER：PlayerState・EnemyState。ChangeState で切り替える

■ シングルトン（singleton）
  意味　：ゲーム全体で 1 つだけ存在する物を、どこからでも使える形
  BRAVER：KdShaderManager、KdEffekseerManager、StageSettings、EffectSettings など（Instance() で取り出す）

■ スマートポインタ（shared_ptr / weak_ptr）
  意味　：使い終わったら自動で片付くポインタ／持ち主にならずに見ているだけのポインタ
  BRAVER：オブジェクトは shared_ptr。カメラやプレイヤーへの参照は weak_ptr（消えた物を触らないように）

■ 名前のない namespace（無名名前空間）
  意味　：そのファイルの中だけで使える名前を作る書き方
  BRAVER：各 .cpp の上の調整用の数値（constexpr）。ほかのファイルとぶつからない

■ constexpr・定数（constant）
  意味　：プログラムの途中で変わらない値
  BRAVER：位置・速さ・色などの調整用の数値は、ほとんど定数にして、ファイルの上にまとめている

■ ヘッダー（.h）とソース（.cpp）
  意味　：「何があるか」を書くファイルと、「どう動くか」を書くファイル
  BRAVER：Player.h ／ Player.cpp・PlayerMove.cpp など

■ リファクタリング（refactoring）
  意味　：動きは変えずに、プログラムを読みやすく整理し直すこと
  BRAVER：2,367 行の Player.cpp を、役割ごとに 7 つのファイルに分けた（中身は 1 文字も変えていない）

■ プリコンパイル済みヘッダー（PCH）
  意味　：よく使うヘッダーを先にまとめてコンパイルし、ビルドを速くする仕組み
  BRAVER：Pch.h（DirectX・imgui・Effekseer などを読み込む）

■ ビルド・コンパイル・リンク（build / compile / link）
  意味　：ソースを機械語にする（コンパイル）→ ライブラリとつなぐ（リンク）→ 実行ファイルを作る（ビルド）
  BRAVER：Visual Studio でビルド。「リンクエラー」は、使う関数の本体（.lib）が見つからない時に出る

■ ライブラリ（library）／ .lib
  意味　：ほかの人が作った便利な部品のまとまり／その機械語のファイル
  BRAVER：DirectXTK・DirectXTex・Effekseer・imgui・tinygltf・nlohmann/json（..\Library）

■ フレームワーク（framework）
  意味　：ゲームの土台になる部品一式
  BRAVER：学校の KdFramework（Src/Framework）。描画・当たり判定・アニメーション・音など

■ 文字コード・UTF-8・BOM・Shift-JIS
  意味　：文字をどんな数字で保存するか／その種類／UTF-8 であることを示す先頭の目印
  BRAVER：日本語を含むソースは BOM 付き UTF-8。imgui の日本語は U8("...") で渡す

■ JSON（ジェイソン）
  意味　：{ "名前": 値 } の形で、設定などを保存する文字のファイル形式
  BRAVER：StageSettings.json・EffectSettings.json（nlohmann/json で読み書き）

 2. 描画の基本（DirectX・シェーダー）
============================================================

■ DirectX 11
  意味　：Windows でグラフィックス（3D・2D）を描くための仕組み
  BRAVER：KdFramework の中で使っている

■ GPU（ジーピーユー）
  意味　：絵を描く専用の計算装置（グラフィックボード）

■ ポリゴン・頂点・メッシュ（polygon / vertex / mesh）
  意味　：3D の形を作る三角形／その角の点／三角形の集まり
  BRAVER：ステージのモデルは Python で三角形を作って書き出した（MakeStageModel.py）

■ テクスチャ（texture）・UV
  意味　：形に貼る画像／画像のどこを貼るかの座標
  BRAVER：石畳・石の壁・扉・鉄・夜空・月・霧・炎など、多くを Python で作った

■ マテリアル（material）
  意味　：表面の質感（色・画像・光り方）の設定

■ シェーダー（shader）・HLSL
  意味　：GPU で動く、色や形を計算する小さなプログラム／その言語
  BRAVER：KdStandardShader（3D）、KdSpriteShader（2D）、KdPostProcessShader（画面全体）

■ 頂点シェーダー・ピクセルシェーダー（vertex shader / pixel shader）
  意味　：頂点の位置を計算する部分／1 ピクセルずつ色を計算する部分

■ 定数バッファ（constant buffer）
  意味　：C++ からシェーダーへ数値を渡す入れ物。C++ とシェーダーで並びと大きさを合わせる必要がある
  BRAVER：霧の設定、画面の白黒・暗さ・周辺減光（cbDepthOfField に追加）

■ ワールド・ビュー・プロジェクション行列（world / view / projection matrix）
  意味　：物の位置と向き／カメラから見た位置／遠近をつけて画面に映す計算
  BRAVER：m_mWorld（物）、カメラの行列、Effekseer にも同じカメラの行列を渡している

■ 行列（matrix）・平行移動・回転・拡大・せん断（シアー）
  意味　：位置・向き・大きさを一度に表す数の表／その種類
  BRAVER：キャラ・カメラ・剣の位置と向きは、すべて行列で表している
          （せん断は、FF7R 風の斜めの HUD の案で使った。今の HUD には入っていない）

■ クォータニオン（quaternion）・球面線形補間（Slerp）・線形補間（Lerp）
  意味　：回転を表す数／2 つの回転の間をなめらかに求める計算／2 つの値の間を求める計算
  BRAVER：剣が速く動いた時、前のフレームとの間の向きを Slerp で求めて当たり判定を置く

■ 描画パス（DrawLit / DrawUnLit / DrawEffect / DrawSprite / GenerateDepthMapFromLight）
  意味　：描く種類ごとに分けた描画の順番
  BRAVER：光が当たる物 → 光の当たらない物（空・月）→ エフェクト（炎・バリア・霧）→ 2D（HUD）

■ ブレンド（blend）・加算合成（additive）・アルファブレンド
  意味　：新しい色と、すでに描いた色の混ぜ方／明るさを足す混ぜ方／不透明度で混ぜる混ぜ方
  BRAVER：炎・バリア・月のにじみ・地面の霧は加算合成

■ アルファテスト（alpha test）
  意味　：不透明度が決めた値より小さいピクセルを描かない処理
  BRAVER：フレームワークのシェーダーは 0.55 未満を描かない。そのため半透明の霧は加算合成にした

■ 深度バッファ・Z バッファ・深度テスト（depth buffer / Z-test）
  意味　：画面の各ピクセルの「奥行き」を覚えておき、手前の物だけを描く仕組み
  BRAVER：エフェクトは「深度を書かない（ZWriteDisable）」で描き、手前の物を消さないようにしている

■ カリング（culling）・両面描画
  意味　：裏向きの面を描かない処理／裏も描く設定（CullNone）
  BRAVER：炎・霧・バリアの板は両面描画

■ レンダーターゲット（render target）
  意味　：画面ではなく、別の画像に描くための描き先
  BRAVER：ポストエフェクトは、いったん別の画像に描いてから加工して画面に出す

■ ビルボード（billboard）
  意味　：いつもカメラの方を向く板
  BRAVER：松明の炎、地面の霧のかたまり、月のにじみ、ヒットエフェクト（カメラの方へ向けて出す）

■ スカイスフィア（sky sphere）
  意味　：カメラを包む大きな球の内側に、空の画像を貼る方法
  BRAVER：半径 150m のドーム（下半分の無い球）に夜空（NightSky.png）を貼り、カメラに付いていく。
          月はドームより手前（120m）に置き、同じく付いていく

■ glTF（ジーエルティーエフ）
  意味　：3D モデルとアニメーションのファイル形式（.gltf ＋ .bin ＋ 画像）
  BRAVER：キャラ・ステージ・空・アニメーションは全部 glTF（tinygltf で読む）

■ スキンメッシュ・ボーン（skinned mesh / bone）
  意味　：骨に合わせて曲がるモデル／その骨
  BRAVER：プレイヤー（SK_Assassin）と敵（Rampage）


============================================================
 3. 光・影・空気
============================================================

■ 平行光（directional light）
  意味　：太陽や月の光のように、一方向から当たる光
  BRAVER：月明かり。斜め横から当てて、体や柱に陰影を付けている（StageEnvironment.h）

■ 環境光（ambient light）
  意味　：どこにでも少しずつ当たる、まわりからの光。影の中の明るさを決める
  BRAVER：ゲームは { 0.36, 0.38, 0.48 }、タイトルは暗めの { 0.22, 0.24, 0.32 }

■ 点光源（point light）
  意味　：電球や松明のように、1 点からまわりへ広がる光
  BRAVER：松明・かがり火・燭台・炉。カメラの近くの 60 個まで登録（StageLights.cpp）

■ ちらつき（flicker）
  意味　：光の明るさを細かくゆらして、炎らしく見せること
  BRAVER：速さの違う sin を 2 つ重ねて、規則正しく見えないようにしている

■ シャドウマップ（shadow map）・深度マップ
  意味　：光から見た奥行きを画像にして、影になる所を求める方法
  BRAVER：プレイヤーのまわり 30m を影の範囲にしている（GenerateDepthMapFromLight）

■ リムライト（rim light）
  意味　：物のふち（輪郭）だけを光らせる光。背景から浮き上がって見える
  BRAVER：プレイヤーはモードの色で薄く、敵は薄い赤。モード切り替えの時は強く光る

■ フォグ（fog）・距離フォグ・高さフォグ
  意味　：遠く・低い所を空気の色に溶かして、奥行きと空気感を出すこと
  BRAVER：距離フォグ（遠くの壁）と高さフォグ（地面の近く）。ステージエディタで調整

■ ソフトパーティクル（soft particles）
  意味　：板の霧などが物に刺さった所を、だんだん薄くして境目を消す方法
  BRAVER：フレームワークに無いので、地面の霧の板が柱に刺さった所が四角く見えた（今は霧を消している）

■ ノイズ（noise）・フラクタルノイズ（fractal noise）
  意味　：自然なムラ・もやもやした模様を作る計算／大きさの違うノイズを重ねたもの
  BRAVER：石・扉・夜空・月・霧のテクスチャを作る時に使った（Python）


============================================================
 4. 画面全体の加工（ポストエフェクト）
============================================================

■ ポストエフェクト（post effect / post-processing）
  意味　：描き終わった画面全体に、あとから色や光の加工をかけること
  BRAVER：KdPostProcessShader。光のにじみ・被写界深度、HP が少ない時の白黒・暗さ・周辺減光

■ ブルーム・ライトブルーム（bloom）
  意味　：明るい所の光が、まわりにふわっとにじむ見え方
  BRAVER：フレームワークの LightBloomProcess

■ 被写界深度（depth of field / DoF）
  意味　：ピントの合っていない所をぼかすこと
  BRAVER：DoF のシェーダーの最後に、白黒・暗さ・周辺減光の処理を足した

■ グレースケール（grayscale）・彩度（saturation）
  意味　：白黒にすること／色の濃さ
  BRAVER：HP が 10% を下回ると色が抜けていき、HP 0 で白黒 0.85（少しだけ色が残る）

■ 周辺減光（vignette／ビネット）
  意味　：画面のふちを暗くすること。視界が狭まったように見える
  BRAVER：HP が少ないほど強くなる。HP 0 でふちがほぼ真っ黒

■ フェードイン・フェードアウト（fade）
  意味　：だんだん見えてくる・だんだん消えていくこと
  BRAVER：タイトルの黒からの登場、倒れた時の暗転（1.5 秒で真っ黒）

■ カラーグレーディング（color grading）
  意味　：画面全体の色味を、場面の雰囲気に合わせて調整すること
  BRAVER：部屋ごとの色（道は青い月明かり、中庭はオレンジ、大聖堂は灰色、玉座の間は赤黒い）の案。まだ入れていない


============================================================
 5. 2D の表示（UI・HUD）
============================================================

■ UI（ユーアイ）・HUD（ヘッド・アップ・ディスプレイ）
  意味　：画面の表示や操作の部分／戦闘中に画面に重ねて出す情報（HP・ATB など）
  BRAVER：左下の HP・モード・ATB ゲージ・技の枠、右下の ATB コマンドと操作ガイド

■ スプライト（sprite）
  意味　：画面に貼る 2D の画像・四角
  BRAVER：KdSpriteShader の DrawTex（画像）・DrawBox（四角）・DrawTriangle（三角）

■ ピボット（pivot）
  意味　：画像を置く時・回す時の基準の点（中心・左下など）

■ スクリーン座標
  意味　：画面の上の位置の数え方
  BRAVER：真ん中が (0, 0)、右が +X、上が +Y。1280 × 720

■ フォント・フォントスプライト（font）
  意味　：文字の形のデータ／文字を画像にして表示する仕組み
  BRAVER：UIText（Zen Old Mincho・Cinzel）。数字が変わった時だけ作り直す

■ グラデーション（gradient）
  意味　：色がだんだん変わっていく表現
  BRAVER：タイトルの光の玉・周辺減光の画像（SpriteUtil）。今の HUD は単色の四角で描いている

■ ダイジェティック UI（diegetic UI）
  意味　：画面に貼る表示ではなく、ゲームの世界の中の物で情報を伝える方法
  BRAVER：バリアの光で残りの敵の数を見せる案、敵の足元の HP の輪の案（まだ入れていない）

■ imgui（ディア・イムグイ）
  意味　：デバッグ用の画面（ボタン・スライダー）を簡単に作るライブラリ
  BRAVER：F8 で出す Player Parameter Editor・Stage Editor・Effect Editor


============================================================
 6. エフェクト（Effekseer）
============================================================

■ Effekseer（エフェクシア）
  意味　：エフェクト（光・火花・斬撃など）を作るツールと、ゲームで再生する仕組み
  BRAVER：斬撃・ヒット・敵の爪・ボスの着地・撃破・ガード・モード切り替えなど（.efkefc）

■ パーティクル（particle）
  意味　：たくさんの小さな粒を飛ばして、火花・煙などを表現する方法
  BRAVER：Effekseer のエフェクト、タイトルの火の粉と光の玉（TitleEmber）

■ ハンドル（handle）
  意味　：再生中のエフェクトを指す番号。位置・色・速さを後から変える時に使う

■ AllColor（オールカラー）
  意味　：再生中のエフェクトの色に、まとめて色を掛ける機能（掛け算なので明るくはできない）
  BRAVER：攻撃のエフェクトをモードの色（青・オレンジ）にする（EffectSettings）

■ Effekseer のネットワーク機能（Server）
  意味　：エディタで編集したエフェクトを、動いているゲームにすぐ反映する仕組み
  BRAVER：Effect Editor の「同期を開始」。ポート 60000。ファイル名でエフェクトを見分ける

■ 剣の軌跡（trail）・Catmull-Rom スプライン
  意味　：剣が通った跡を帯で描く表現／点と点の間をなめらかな曲線でつなぐ計算
  BRAVER：KdTrailPolygon。剣の根元と先端を毎フレーム記録し、間を曲線で補って帯にする（SwordTrail.txt）

 7. アニメーション
============================================================

■ キーフレーム（keyframe）
  意味　：アニメーションの「決めの姿勢」。その間はなめらかに補われる

■ ブレンド（animation blend）
  意味　：前の動きから次の動きへ、数フレームかけてなめらかに混ぜること

■ リターゲット（retarget）
  意味　：別のキャラ用のアニメーションを、別の体に合わせて使うこと
  BRAVER：UE5 で SK_Assassin に合わせて書き出した（UE_Retarget_Guide.txt）

■ ルートモーション（root motion）
  意味　：アニメーションの中で体が進んだ分だけ、キャラを実際に動かすこと（足が滑らない）

■ アニメーションの解析
  意味　：アニメーションの骨の位置を数値で調べて、プログラムを合わせること
  BRAVER：踏み切り・着地・叩きつけのフレームを、足や剣の骨の高さから求めている

■ 初期姿勢（rest pose / T ポーズ）
  意味　：アニメーションを当てる前の、モデルの元の姿勢


============================================================
 8. 当たり判定と物理
============================================================

■ コライダー（collider）・当たり判定
  意味　：ぶつかったかを調べる見えない形
  BRAVER：KdCollider。ステージは「地面（TypeGround）」と「壁（TypeBump）」として登録

■ レイ（ray）・レイキャスト
  意味　：線を飛ばして、何に当たるかを調べる方法
  BRAVER：足元の地面を探す、壁のすり抜けを防ぐ、飛びかかる前に柱が無いかを調べる

■ 球（sphere）の判定・押し出し
  意味　：球が壁にめり込んだ分だけ、外へ押し出す方法
  BRAVER：BumpHit。体の高さの違う所に 2 つの球を置いて押し出す。敵は体の大きさに合わせて半径を変える

■ OBB（向きを持った箱）
  意味　：回転できる箱の当たり判定
  BRAVER：剣の刃を包む細長い箱。速く振った時は、前のフレームとの間にも箱を置く（すり抜け防止）

■ 主成分分析（PCA）
  意味　：点の集まりが、一番長く伸びている向きを求める計算
  BRAVER：剣のモデルの頂点から、刃の向きと長さを自動で求める

■ 重力・着地予測
  意味　：毎フレーム下向きの速さを足す／あと何フレームで地面に着くかを計算すること
  BRAVER：落ちる時だけ重力を強くして、ふわふわしないようにしている

■ 無敵時間（invincible time）
  意味　：攻撃を受けた後、少しの間ダメージを受けない時間


============================================================
 9. 操作・入力
============================================================

■ XInput（エックスインプット）
  意味　：Windows で Xbox コントローラーを読む仕組み
  BRAVER：InputHelper.h の GamePad。スティック・ボタン・トリガー

■ デッドゾーン（dead zone）
  意味　：スティックを少し倒しただけでは反応しないようにする範囲（手のぶれ対策）

■ 入力の割り当て（key binding）
  意味　：どのキー・ボタンで、どの操作をするかの対応
  BRAVER：InputHelper.h の Bind。キーボードとパッドの両方を 1 つの名前で扱う（例：GuardDash = Shift ／ RB）

■ 押した瞬間（トリガー）・押している間
  意味　：ボタンが押されたフレームだけ反応する／押している間ずっと反応する
  BRAVER：KeyTrigger クラス

■ 先行入力（input buffer）
  意味　：ボタンを押してから少しの間、その入力を覚えておくこと
  BRAVER：10 フレーム


============================================================
 10. ゲームの手ごたえ・演出
============================================================

■ ヒットストップ（hit stop）
  意味　：攻撃が当たった瞬間に、少しだけ動きを止めて手ごたえを出すこと
  BRAVER：普通 4 フレーム、クリティカル 7 フレーム（HitStop.h）

■ カメラシェイク（camera shake）
  意味　：画面を少し揺らして、衝撃を伝えること

■ スローモーション（slow motion）・タイムスケール
  意味　：時間の進み方を遅くすること／その倍率
  BRAVER：ATB コマンドを開いている間は 10 分の 1（GameTime）

■ キャンセル（cancel）
  意味　：動きの途中で、次の動きに移れるようにすること

■ ロックオン（lock-on）
  意味　：近くの敵に自動で狙いを合わせること
  BRAVER：10m 以内の一番近い敵

■ ガードブレイク（guard break）
  意味　：ガードの耐久値が 0 になり、ガードを崩されること


============================================================
 11. ゲームの仕組み（バトル）
============================================================

■ ATB（アクティブ・タイム・バトル）
  意味　：ゲージがたまると、特別な行動（技）が使える仕組み（FF7 リメイク風）
  BRAVER：攻撃を当てる・回避するとたまる。2 本までためられる

■ CT（クールタイム／cool time）
  意味　：技を使った後、もう一度使えるまでの待ち時間

■ バトルモード（オペレーター／パニッシャー）
  意味　：同じキャラで、戦い方を切り替える仕組み
  BRAVER：オペレーター（速く・ゲージがたまる）／パニッシャー（遅く・強い）。E ／ Y で切り替え

■ スーパーアーマー（super armor）
  意味　：攻撃を受けても、のけぞらない状態

■ ブレイク（stagger）
  意味　：敵のゲージをためて、大きくよろけさせる仕組み（FF7R。BRAVER にはまだ無い）


============================================================
 12. ステージ作り
============================================================

■ プロシージャル生成（procedural generation）
  意味　：形や画像を、手で作らずプログラムの計算で作ること
  BRAVER：ステージ・テクスチャ・夜空・月・霧・炎などを Python で作った（Tools/）

■ 見えない当たり判定（ピラーガード）
  意味　：見た目の形とは別に、キャラが引っかからないよう単純な箱で判定を置くこと
  BRAVER：柱・家具のまわり（RuinedRoadCollision.gltf）

■ バリア（barrier）
  意味　：先へ進めないようにする壁。条件を満たすと開く
  BRAVER：その部屋の敵を全員倒すと開く

■ ステージエディタ・エフェクトエディタ
  意味　：ゲームを動かしたまま、見た目の数値を調整できる画面
  BRAVER：F8。霧・HP が少ない時の画面・エフェクトの大きさと色

 13. 音

============================================================
 14. 道具・ファイルの形式
============================================================

■ Visual Studio：C++ を書いてビルドする道具
■ UE5（Unreal Engine 5）：アニメーションのリターゲットに使った
■ Effekseer エディタ：エフェクトを作る道具
■ Blender：3D モデルを作る道具（空のモデル）
■ Python（numpy・Pillow）：ステージ・テクスチャ・音の変換を作るスクリプト

■ .gltf / .bin：3D モデル
■ .png：画像（透明も持てる）
■ .wav / .mp3：音
■ .efkefc / .efkproj：Effekseer のエフェクト
■ .csv：表のデータ（松明の位置など）
■ .json：設定のデータ
■ .hlsl / .shaderInc：シェーダー／コンパイル済みのシェーダー
■ .vcxproj / .filters：Visual Studio のプロジェクト（どのファイルをビルドするか）


============================================================
 15. Git（ソースの管理）
============================================================

■ Git・リポジトリ（repository）
  意味　：ファイルの変更の歴史を残す仕組み／その保管場所
■ コミット（commit）：変更を 1 つの記録として残すこと
■ プッシュ（push）／プル（pull）：GitHub へ送る／GitHub から取ってくる
■ ブランチ（branch）：作業の流れを分ける枝。BRAVER は claude/zealous-darwin-oy746i で作業
■ マージ（merge）：別のブランチの変更を合わせること
■ .gitignore：Git に入れないファイルを決めるリスト（Library・ビルドの結果など）
■ GitHub のファイルの上限：1 ファイル 100MB まで
■ Fork：Git を画面で操作する道具

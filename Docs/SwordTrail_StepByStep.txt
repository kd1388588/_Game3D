============================================================
 剣のトレイル（軌跡）を、処理の順番どおりに細かく説明
============================================================

※ かんたんな説明：SwordTrail.txt ／ 関数・用語の一覧：SwordTrail_Detail.txt
※ この資料は「1フレームの中で、何が、どの順番で、どんな計算で行われるか」を、
   コードと数字つきで追いかける版です。

  ステップ0　準備（起動した時に1回だけ）
  ステップ1　剣の行列を作る（毎フレーム PostUpdate）
  ステップ2　軌跡を足すか決める（毎フレーム、攻撃のステート）
  ステップ3　刃の根元と先端の位置を求める
  ステップ4　Catmull-Rom 曲線で、間を6つに分ける
  ステップ5　帯の「1本の線」を表す行列を作る
  ステップ6　KdTrailPolygon が、行列から帯（三角形）を作る
  ステップ7　振っていないフレームは短くする
  ステップ8　画像を貼って、加算合成で描く
  おまけ　　 数字で見る1回の振り／よくある質問


============================================================
 ステップ0　準備（Player::Init、起動した時に1回だけ）
============================================================

■ 0-1　刃の形を、剣のモデルから求める（CalcBladeShape）
  キャラのモデルには、剣のメッシュ（SM_Blade_R / SM_Blade_L）が入っている。
  そのメッシュの頂点（形を作る点）を全部調べて、次の3つを求める。

    localHand … 手の位置（＝剣を握っている所）
    localDir  … 刃が伸びている向き
    tipLength … 手から刃先までの長さ

  求め方（主成分分析）
    ① 頂点の平均＝剣の真ん中（center）を求める。
    ② 「頂点が一番長く散らばっている向き」を求める。
       各頂点の (位置 − 真ん中) から 3×3 の行列（共分散行列）を作り、
       適当な向き (1,1,1) に、その行列を 32 回かけ続ける。
       かけるたびに、一番散らばっている向き（＝細長い剣の中心線）に近づいていく（べき乗法）。
    ③ 中心線の上で、頂点が一番遠くまである両端を求める。
    ④ ノードの原点（＝手）に近い方が柄、遠い方が刃先。刃先までの距離が tipLength。

  → 剣のモデルを差し替えても、刃の長さ・向きを自動で合わせてくれる。
    刃の根元（つば）は、手から 0.1m（ただし刃の半分より短く）の所にしている。
      m_swordBladeBaseY = min(0.1, tipLength × 0.5)
      m_swordBladeTipY  = tipLength

■ 0-2　帯の入れ物を作る
  右と左の剣に1つずつ、SwordTrail という入れ物を用意する。

    struct SwordTrail
    {
        std::shared_ptr<KdTrailPolygon> polygon;   // 帯そのもの（フレームワークのクラス）
        std::deque<Math::Vector3> baseHistory;     // 刃の根元の位置の記録（新しい順、2個まで）
        std::deque<Math::Vector3> tipHistory;      // 刃の先端の位置の記録（新しい順、2個まで）
    };

    polygon->SetLength(15 × 6);   … 帯の線は最大 90 本（15フレーム分 × 1フレーム6本）
    polygon->SetMaterial(画像);    … 今のモードの画像（青かオレンジ）を貼る


============================================================
 ステップ1　剣の行列を作る（Player::PostUpdate → UpdateWeaponMatrix）
============================================================

  CalcBladeMatrix(shape) で、剣の「ワールド行列」（ゲームの世界での位置・向き）を作る。

    nodeMat = 剣のノードの行列（アニメーションで動いた後） × プレイヤーの行列
    手の位置   = localHand を nodeMat で変換
    刃の向き   = localDir  を nodeMat で回す（＝行列の Y軸 にする）
    X軸・Z軸  = 刃の向きと直角になるように作る

  → できた行列は「原点が手、Y軸が刃の向き（長さ1）」。
    m_swordWorldR / m_swordWorldL に入れる。

  ※ PostUpdate で作るので、次のステップ2（Update）で使う時は「1フレーム前の姿勢」になる。
    （そのため、叩きつけの軌跡は、叩きつけた後も1フレーム多く出すなどの調整をしている）


============================================================
 ステップ2　軌跡を足すか決める（PlayerStateComboAttack::Update）
============================================================

  攻撃のステートが、毎フレーム IsTrailFrame(アニメーションのフレーム) を調べる。

    | 攻撃                 | 軌跡を出すフレーム                                       |
    |----------------------|----------------------------------------------------------|
    | 普通の攻撃           | 10 ～ 45（攻撃判定と同じ）                               |
    | 溜め攻撃 4-3 Start   | 2 ～                                                     |
    | 溜め攻撃 4-3 Loop    | ずっと                                                   |
    | 溜め攻撃 4-3 End     | 右の剣先が足元から 0.15m より下に来るまで（最大15）      |
    | 04の4段目            | 1 ～ 叩きつけるフレーム＋1（起動時にアニメから求める。49）|
    | 02の3段目（回転）    | 4 ～ 80                                                  |

  true なら player->AddSwordTrailPoints() を呼ぶ。

    void Player::AddSwordTrailPoints()
    {
        if (!m_isTrailActive)            // 前のフレームは振っていなかった＝新しい振りの始まり
        {
            ClearSwordTrail(右); ClearSwordTrail(左);   // 前の振りの帯を全部消す（つながらないように）
        }
        AddSwordTrailSample(右の帯, m_swordWorldR);
        AddSwordTrailSample(左の帯, m_swordWorldL);
        m_isTrailActive = true;           // 今、振っている
        m_isTrailAddedThisFrame = true;   // このフレームは足した（ステップ7で短くしない）
    }


============================================================
 ステップ3　刃の根元と先端の位置を求める（AddSwordTrailSample の最初）
============================================================

    base = GetSwordPoint(剣の行列, m_swordBladeBaseY);   // 根元
    tip  = GetSwordPoint(剣の行列, m_swordBladeTipY);    // 先端

    GetSwordPoint(行列, y) = (0, y, 0) を行列で変換した点

  剣の行列は「原点が手、Y軸が刃の向き」なので、
  (0, 0.1, 0) は手から刃の向きに 0.1m 進んだ所＝根元、
  (0, tipLength, 0) は刃先、になる。


============================================================
 ステップ4　Catmull-Rom 曲線で、間を6つに分ける（★なめらかさの秘密）
============================================================

■ なぜ必要か
  回転するような速い攻撃では、剣先は1フレームに 1m 近く動く。
  毎フレームの位置をそのまま線でつなぐと、角ばった多角形の帯になってしまう。

■ やっていること
  「前のフレームの位置」と「今のフレームの位置」の間に、曲線の上の点を 5 個足して、
  合わせて 6 本の線にする（kSwordTrailSubdivision = 6）。

  曲線を決めるのに、4つの点を使う（根元と先端で、それぞれ別に計算する）。

    p0 = 2つ前のフレームの位置（記録が1個しか無ければ、1つ前と同じ）  … baseHist[1]
    p1 = 1つ前のフレームの位置                                        … baseHist[0]
    p2 = 今のフレームの位置                                           … base
    p3 = この先の予測位置 ＝ 今 ＋ (今 − 1つ前)                       … 同じ速さで進むと仮定

    for (i = 1 ～ 6)
    {
        t = i / 6;                                   // 0.17, 0.33, 0.5, 0.67, 0.83, 1.0
        b = CatmullRom(base0, base1, base, base3, t); // 根元の曲線上の点
        e = CatmullRom(tip0,  tip1,  tip,  tip3,  t); // 先端の曲線上の点
        polygon->AddPoint(CreateTrailMatrix(b, e));   // ステップ5へ
    }

■ Catmull-Rom 曲線とは
  p1 と p2 の間を、t（0～1）で進む曲線。
    ・t = 0 で p1、t = 1 で p2 をちょうど通る。
    ・p1 での曲がり方は (p2 − p0)、p2 での曲がり方は (p3 − p1) の向きに合わせる。
  → 前後の点を見て「どっちから来て、どっちへ行くか」を考えるので、つなぎ目が角ばらない。
  （式：0.5 × { 2p1 + (−p0 + p2)t + (2p0 − 5p1 + 4p2 − p3)t² + (−p0 + 3p1 − 3p2 + p3)t³ } ）

■ 最後に記録を更新
    baseHist.push_front(base);  tipHist.push_front(tip);     // 新しい位置を先頭に
    2個より多ければ pop_back で一番古いものを捨てる              // いつも直近2フレーム分

  ※ 振り始めの1フレーム目は、記録が無いので曲線は作らず、その位置の線を1本だけ足す。


============================================================
 ステップ5　帯の「1本の線」を表す行列を作る（CreateTrailMatrix）
============================================================

  KdTrailPolygon は「行列」を1つ受け取るごとに、帯の横線を1本作る。
  そのルール（KdTrailPolygon::CreateVerticesWithDefaultPattern）は次のとおり。

    幅   w   = 行列の X軸の長さ × 0.5
    頂点1    = 行列の位置 + X軸の向き × w × 0.5
    頂点2    = 行列の位置 − X軸の向き × w × 0.5
    → 2つの頂点の間の長さ ＝ X軸の長さ × 0.5

  そこで、刃とぴったり同じ線になるように、次の行列を作っている。

    X軸   = (先端 − 根元) × 2      … 向きは刃の向き。長さは刃の2倍（× 0.5 されて刃の長さになる）
    位置  = (根元 + 先端) × 0.5    … 刃の真ん中

    → 頂点1 ＝ 先端、頂点2 ＝ 根元 になる。


============================================================
 ステップ6　KdTrailPolygon が、行列から帯（三角形）を作る
============================================================

  ■ AddPoint(行列)
      m_pointList.push_front(行列);              // 新しい線を先頭に入れる
      90 本より多くなったら pop_back で一番古い線を消す

  ■ 描く時に、線のリストから頂点を作る
      線 i（0 が一番新しい）ごとに頂点を2つ作り、
        UV の横（U）：頂点1（先端）= 0、頂点2（根元）= 1
        UV の縦（V）：i ÷ (線の数 − 1)  … 一番新しい線が 0、一番古い線が 1
      となりの線どうしの頂点を、三角形のひもでつないで帯にする。

        新しい ── 線0 ─ 先端●━━━━━━●根元   V = 0
                  線1 ─ 先端●━━━━━━●根元
                  線2 ─ 先端●━━━━━━●根元
                   …
        古い   ── 線N ─ 先端●━━━━━━●根元   V = 1
                         U=0             U=1

    → 画像の「左上」が刃先の一番新しい所、「右下」が根元の一番古い所に貼られる。


============================================================
 ステップ7　振っていないフレームは短くする（Player::Update → UpdateSwordTrails）
============================================================

  攻撃のステートの Update の後で、毎フレーム呼ばれる。

    void Player::UpdateSwordTrails()
    {
        if (m_isTrailAddedThisFrame) return;   // このフレームは足したので、何もしない
        m_isTrailActive = false;               // 振り終わった（次に足す時は新しい振り）
        ShrinkSwordTrail(右); ShrinkSwordTrail(左);
    }

    ShrinkSwordTrail … DelPointBack() を 6 回（＝1フレームで足す本数と同じ）呼んで、古い線から消す

  → 振り終わってから、帯が古い方から短くなって、約 15 フレーム（0.25 秒）で消える。
    （m_isTrailAddedThisFrame は、毎フレームの最初に false に戻している）


============================================================
 ステップ8　画像を貼って、加算合成で描く
============================================================

■ 画像（Asset/Textures/Trail/、Tools/MakeTrailTexture.py で作成、64×256）
    横（U：刃先 → 根元）  明るさ ＝ 0.15 ＋ 0.85 × (1 − U)^1.5   … 刃先ほど明るく、根元は 15%
                          両端はふちをぼかす
    縦（V：新しい → 古い）明るさ ＝ (1 − V)^1.5                 … 古いほど暗く
                          一番新しい所（剣のすぐ後ろ）は少しだけぼかす
    芯                    刃先の新しい所だけ、白に近づける（(1 − U)^6）
    色                    オペレーター：青 (0.25, 0.65, 1.0)
                          パニッシャー：オレンジ (1.0, 0.4, 0.08)
    ※ 画像ファイルが無い時は、CreateSwordTrailTexture() が同じ計算で画像をプログラムで作る。
    ※ モードを切り替えた時は ApplySwordTrailTexture() で画像を差し替える。

■ 描き方（Player::DrawEffect）
    ・CullNone（裏面も描く）       … 帯を裏から見ても消えない
    ・Add（加算合成）              … 色を後ろの色に足すので光って見える。黒い所は何も足さない＝透明
    ・ZWriteDisable（深度を書かない）… 帯の暗い所が、後ろのエフェクトや物を隠さない
    ・m_StandardShader.DrawPolygon(帯) を右と左で2回。


============================================================
 おまけ1　数字で見る1回の振り（普通の攻撃）
============================================================

  フレーム 10　　 振り始め。前の帯を消して、線を1本だけ足す（記録が無いので曲線なし）
  フレーム 11　　 1つ前（10）と今（11）の間を曲線で6本 → 7本
  フレーム 12　　 さらに6本 → 13本
    …
  フレーム 25　　 6 × 15 ＋ 1 ＝ 91本 → 上限 90本を超えるので、一番古い線が消える
    …（ここからは、足す6本と消える6本が同じになり、15フレーム分の長さのまま剣を追いかける）
  フレーム 45　　 最後に足す
  フレーム 46～　 足さないので、毎フレーム 6本ずつ消える → 約15フレームで消える


============================================================
 おまけ2　よくある質問
============================================================

  Q. なぜ1フレームを6つに分けるの？
  A. 速く振ると、1フレームに剣先が 1m 近く動くからです。分けないと角ばった帯になります。
     6 より多くするともっとなめらかになりますが、線の数が増えて重くなります。

  Q. 「予測位置」p3 は何のため？
  A. Catmull-Rom 曲線は p0～p3 の4点が必要ですが、「次のフレームの位置」はまだ分かりません。
     そこで「今と同じ速さで進む」と仮定して、今 ＋ (今 − 1つ前) を代わりに使っています。

  Q. 右と左の帯はどう分けているの？
  A. SwordTrail を2つ（m_swordTrailR / m_swordTrailL）持ち、同じ処理をそれぞれの剣の行列で行っています。

  Q. 帯が刃からずれないのはなぜ？
  A. 刃の長さと向きを、剣のメッシュの頂点から自動で求めているからです（ステップ0）。
     帯の線は、その刃の根元から先端までと、ぴったり同じ長さにしています（ステップ5）。

  Q. 振り終わった後、帯がすぐ消えないのはなぜ？
  A. 一気に消さず、毎フレーム古い方から6本ずつ消しているからです（ステップ7）。
     剣のあとを追いかけるように、スーッと消えて見えます。

  Q. タイトル画面のキャラの軌跡も同じ？
  A. はい。TitleChara も、Player の CalcBladeShape / CalcBladeMatrix / GetSwordPoint /
     CreateTrailMatrix と、同じ Catmull-Rom の補間を使っています。

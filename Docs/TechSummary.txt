============================================================
 0. ゲーム全体の作り
============================================================

■ 使っているもの
  C++ / DirectX 11 / Visual Studio。学校の KdFramework（描画・当たり判定・
  アニメーションの土台）の上に、ゲームの部分を作っている。

■ ゲームオブジェクト（KdGameObject）
  【何か】  プレイヤー・敵・カメラ・UI など、画面に出るものは全部「オブジェクト」。
  【仕組み】シーンがオブジェクトのリストを持ち、毎フレーム全員の Update（動き）→
            PostUpdate（後片付け）→ Draw（描画）を順番に呼ぶ。
  【理由】  どのオブジェクトも同じ呼ばれ方になるので、増やすのが簡単。

■ キャラクターの共通部分（BaseChara）
  【何か】  プレイヤーと敵で共通の処理（アニメーション・重力・地面との判定・
            押し出し・HP・ルートモーション）をまとめた親クラス。
  【理由】  同じ処理を2回書かないため。直す時も1か所で済む。
  【場所】  Src/Application/GameObject/Character/Base/BaseChara

■ ステートパターン（PlayerState・EnemyState）
  【何か】  「待機」「走る」「攻撃」「回避」「ジャンプ」「ガード」などの状態ごとに
            クラスを分け、今の状態のクラスの Update だけを動かす。
  【仕組み】状態を変える時は ChangeState(新しい状態) を呼ぶ。
            新しい状態の ChangeState で最初の準備（アニメーションの再生など）、
            毎フレーム Update で入力を見て、次の状態へ変えるかを決める。
  【理由】  状態が10個以上あり、if や switch で書くと1つの関数がとても長くなる。
            クラスに分けると、1つの状態の処理が1か所にまとまって読みやすい。
  【場所】  Player/PlayerState.h・.cpp、Enemy/EnemyState.h・.cpp

■ 時間の数え方
  ゲームは 1秒間に 60回 更新する。「60フレーム = 1秒」。
  アニメーションの長さ、無敵時間、CT（クールタイム）なども、すべてフレーム数で数えている。


============================================================
 1. アニメーション
============================================================

■ 再生とブレンド（KdAnimator）
  【何か】  アニメーションを切り替える時、前の動きから次の動きへ数フレームかけて
            なめらかに混ぜる（ブレンド）。
  【理由】  パッと切り替えると、体が一瞬で別の姿勢にワープして見えるため。

■ リターゲット（アニメーションを別の体に合わせる）
  【何か】  別のキャラ用に作られたアニメーションを、このゲームのキャラの体に合わせて使う。
  【仕組み】① UE5（Unreal Engine）で、元のキャラから SK_Assassin へリターゲットして書き出し。
            ② ゲーム側でも、骨を「名前」で対応づけ、体格の違い（腰の高さの比率）で
               移動量を拡大・縮小している。
  【理由】  アニメーションを1から作るのは時間がかかるため、既存のものを活かした。

■ 初期姿勢へのリセット（ResetPoseToRest）
  【何か】  毎フレーム、アニメーションを当てる前に全部の骨を「初期姿勢」に戻す。
  【理由】  アニメーションにデータが無い骨（剣など）が、前のアニメーションの姿勢のまま
            残ってしまうのを防ぐため。

■ ルートモーション（アニメーションの動きどおりに移動する）
  【何か】  アニメーションの中で腰が前へ進んだ分だけ、キャラ自体を前へ動かす。
  【仕組み】① 毎フレーム、アニメーションの腰の水平位置を調べ、前のフレームとの差を出す。
            ② 腰は体の中心に固定し、その差の分だけキャラの位置を動かす。
            ③ キャラの向きに合わせて回転してから足す。
  【理由】  プログラムで決まった速さで動かすと、足の動きと移動が合わず「足が滑って」見える。
            アニメーションどおりに動かすと、足が地面にしっかり着いて見える。
            また、攻撃の踏み込みも自然になる。
  【工夫】  走る速さを上げる時は、再生速度で6割・移動の倍率で4割上げる。
            （再生速度だけだと足がせわしなく、倍率だけだと足が滑るため）


============================================================
 2. ジャンプ（アニメーションを数値で解析して合わせた）
============================================================

  ジャンプは「アニメーションの見た目」と「プログラムの物理（重力）」を合わせるのが難しく、
  何度も直した部分。最後は、アニメーションのファイルを Python で1フレームずつ計算して、
  骨の高さを数値で調べてから合わせた。

■ 調べて分かったこと
  ・ジャンプ開始：0～8フレームでしゃがみ、12フレーム目で足が地面から離れる。
  ・空中：腰の高さはほぼ一定。
  ・着地：10フレーム目で足が着き、その後しゃがんで衝撃を受け止める。

■ 合わせ方
  ・踏み切り：アニメーションで足が離れるフレームになってから、キャラを上へ飛ばす。
              （すぐ飛ばすと、しゃがんだまま宙に浮いて見える）
  ・ためを短く：踏み切りの6フレーム前から再生して、ボタンを押してすぐ跳ぶようにした。
  ・着地：「あと何フレームで地面に着くか」を重力から計算し（着地予測）、
          ちょうど着地の瞬間に、アニメーションの「足が着いたフレーム」になるよう、
          着地のアニメーションを少し前から始める。
  ・空中でつぶれるバグ：着地のフレームを「足首」の骨で調べていたため、しゃがむと
          かかとが浮いて間違えていた（29フレーム目と判定）。
          「つま先の付け根」の骨で調べるようにして、正しい 10フレーム目になった。
  ・二重に高くならないように：プログラムで飛ばしているので、空中ではアニメーションで
          腰が上がりすぎないよう上限を付けた。
  ・ふわふわしないように：落ちる時だけ重力を 1.5倍 にした。
  【場所】  PlayerState.cpp の PlayerStateJump、BaseChara の CalcFootLiftFrame /
            CalcFootPlantFrame / PredictLandingFrames


============================================================
 3. 操作の気持ちよさ
============================================================

■ 先行入力（入力バッファ）
  【何か】  ボタンを押してから 10フレームの間は「押された」ことを覚えておく。
  【理由】  技の終わり際に少し早めに押した入力が無視されると、操作が「もっさり」する。
            アクションゲームでよく使われる方法。
  【場所】  Player.cpp の UpdateInputBuffer

■ キャンセル
  【何か】  攻撃や回避の途中でも、決まったフレームを過ぎたら次の行動に移れる。
            ・攻撃 → 12フレーム以降は回避で、少したてば移動・ジャンプでキャンセル
            ・回避 → 55% 進んだら攻撃・移動でキャンセル
  【理由】  動きの最後まで待たされると、思いどおりに動けずストレスになるため。

■ 回避（右クリック）
  ・移動キーの方向へすぐ向いてから転がる。再生速度 1.8倍（距離は同じで素早く）。

■ ダッシュとガード（Shift）
  ・走っている時に Shift → ダッシュ（1.6倍の速さ）
  ・止まっている時に Shift → ガード（7. を参照）


============================================================
 4. 攻撃の当たり判定と手ごたえ
============================================================

■ OBB（向きを持った箱）の当たり判定
  【何か】  剣の刃を包む、細長い箱で当たり判定をする。
  【理由】  剣は細長く、振るたびに向きが変わる。丸（球）の判定だと当たりすぎるので、
            剣の向きに合わせて回る箱にした。

■ 剣の形を自動で求める（主成分分析）
  【何か】  剣のモデルの頂点から「一番長く伸びている向き（＝刃の向き）」と長さを計算し、
            判定の箱と剣の軌跡を、実際の刃にぴったり合わせる。
  【仕組み】頂点がどの向きに一番広がっているかを計算する（主成分分析）。
  【理由】  手で位置を合わせると、モデルを変えるたびに合わなくなるため。

■ 無敵時間
  ・敵は攻撃を受けると 30フレーム無敵になる。同じ攻撃が何十回も当たらないようにするため。

■ ヒットストップ
  【何か】  攻撃が当たった瞬間に、プレイヤーも敵も数フレームだけ止め、画面を少し揺らす。
  【仕組み】ゲーム全体で1つの仕組み（HitStop）。当たった時に「止める長さ」を登録すると、
            プレイヤーも敵も Update の最初で「止まっている途中か」を見て、動きを止める。
            普通 4フレーム、クリティカル 7フレーム、重い攻撃は +2。
  【理由】  当たった「手ごたえ」が出て、攻撃が気持ちよくなる。
            当たり判定の中で自動でかけるので、どの攻撃にも同じルールでかかり、書き忘れない。
  【場所】  Src/Application/Utility/HitStop.h


============================================================
 5. バトルモードと ATB（FF7リメイク風）
============================================================

■ バトルモード（E キーで切り替え）
  ・オペレーター：普通の速さ。左クリックは攻撃01。時間でも ATB がたまる。
  ・パニッシャー：動きは遅い（0.7倍）が攻撃が重い（1.5倍）。左クリックは攻撃02。
                  攻撃を当てると ATB が2倍たまる。
  【仕組み】モードによって「倍率」を変えるだけ。移動・ダメージ・ゲージのたまり方の
            計算に、その倍率を掛けている。
  【理由】  処理を2つずつ書かずに済み、数字を変えるだけで調整できる。
  ・切り替えた瞬間は、体のふちが光る（オペレーターは青、パニッシャーはオレンジ）。

■ ATB ゲージ
  ・2本までためられる。攻撃を当てる（+12）・時間（オペレーターだけ）でたまる。
  ・ゲージを使って、ATB コマンドの技（6.）を出す。



============================================================
 6. ATB コマンド（スローモーション）
============================================================

  【何か】  F キーでメニューを開くと、時間が 10分の1 になり、
            攻撃04（ゲージ1本）・攻撃05（ゲージ2本）から技を選ぶ。選ぶと最後まで自動で出す。
  【仕組み】
    ・時間の速さ（GameTime）：ゲーム全体の「時間の速さ」を1つ持ち、
      アニメーションの進む量・重力・エフェクトの再生速度に掛けている。
      0.1 にすると、全部が10分の1の速さで動く。
    ・メニューを開いている間、敵は「考える処理（攻撃する・近づく）」を止め、
      アニメーションだけゆっくり動く。
    ・CT（クールタイム）：技を使った後、決まった時間はもう一度使えない（04 は3秒、05 は8秒）。
    ・攻撃05の後は5秒間オペレーターに固定（モードを切り替えられない）。
    ・技を受けた敵は、のけぞり続けて反撃してこない。
  【理由】  FF7リメイクのように、落ち着いて技を選べて、技を出す瞬間が目立つため。
  【場所】  Src/Application/Utility/GameTime.h、Player.cpp の UpdateCommandMenu、
            UI/Gage/ATB/ATBCommandMenu


============================================================
 7. ガード（構え・ガード歩き・ガード崩し）
============================================================

  ・止まっている時に Shift で構える（構える → 構えたまま → 解く、の3つのアニメーション）。
  ・ガード中は受けるダメージが 2割、のけぞらない。受け止めた時は専用のアニメーション。
  ・構えたまま移動キーで、ガードしながら歩ける（普段の半分の速さ）。
    【工夫】8方向の歩きのアニメーションを、進む方向に一番近いものから選ぶ。
            どのアニメーションがどの方向へ進むかは、起動時にアニメーションの動きを
            計算して決めている（左右の取り違えを防ぐため）。
  ・ガードの耐久値：受け止めるたびに減り、0 になると「ガード崩し」でよろけ、2秒ガードできない。
  【場所】  PlayerState.cpp の PlayerStateGuard / PlayerStateGuardBreak


============================================================
 8. カメラとロックオン
============================================================

■ 三人称カメラ（TPSCamera）
  ・マウスで回せる。壁があればカメラを手前に寄せて、壁の中に入らないようにする。
  ・高さは「足元の高さ＋決まった高さ」に、なめらかに付いていく。
    【理由】腰の骨に付けると、回避で腰が下がった時にカメラがガクンと動くため。
  ・左右に動くと、カメラもその方向へ少し回り込む（進む先が見えやすい）。
  ・ヒットストップ中は画面を少し揺らす。

■ ロックオン（ホイールクリック / R キー）
  【何か】  15m 以内の一番近い敵に視点を合わせ、赤いマークを出す。
  【仕組み】
    ・敵のリストから、一番近い敵を探す。
    ・カメラは「プレイヤーから敵への向き」へなめらかに回る。
    ・敵の胸の位置を「画面の座標」に変換して、そこにマークを描く。
    ・攻撃を振り始める時だけ敵の方を向き、振っている途中は向きを変えない。
    ・敵を倒す・離れすぎると、近くの別の敵に切り替わる。
  【理由】  1体ずつしっかり倒すゲームなので、狙った敵を見失わないため。
            ずっと敵を向き続けると攻撃の踏み込みの向きが途中で変わって不自然なので、
            振り始めだけ向くようにした。


============================================================
 9. 見た目の演出
============================================================

■ 剣の軌跡（トレイル）
  【何か】  刃の根元と先端の位置を毎フレーム記録し、それをつないだ帯（リボン）を、
            光る絵で描く。
  【流れ】  ・攻撃が当たるフレームの間：毎フレーム、左右の剣の「刃の根元」と「刃の先端」の
              位置を記録して、帯の形にする。
            ・攻撃していない時：帯を古い方から少しずつ消す（後ろから縮むように消える）。
            ・次の振りが始まった時：前の振りの帯とつながらないよう、一度全部消してから記録し直す。
  【工夫1】刃全体から出す
            根元と先端の2点の間を帯の幅にしているので、刃の真ん中の線だけでなく、
            刃全体から軌跡が出る。
  【工夫2】きれいな弧にする（Catmull-Rom 曲線）
            剣は1フレームで大きく動くので、フレームごとの位置を直線でつなぐと
            カクカクした多角形になる。そこで、前のフレームと今のフレームの間に
            「なめらかな曲線の上の点」を6個ずつ足している。
            Catmull-Rom 曲線は、前後の位置から「この辺を通るはず」という曲線を作る計算。
  【工夫3】絵はプログラムで作る
            画像ファイルを使わず、起動時に軌跡用の絵を計算で作っている。
            ・刃の先端側ほど明るく、根元側ほど暗い
            ・剣のすぐ後ろほど明るく、古い所ほど暗い
            ・先端付近の新しい所は、白っぽく光る「芯」にする（色は水色）
  【工夫4】加算合成で描く
            色を足し算する描き方。重なるほど明るくなり、光って見える。
            黒は足しても変わらないので、絵の暗い部分は透明に見える。
            ※普通の「半透明」を使わない理由：このゲームの3D用シェーダーは
              「透明度が55%より薄い所は描かない」作りなので、ぼかした部分が全部消えてしまうため。
  ・軌跡の長さは15フレーム分。裏側からでも見え、後ろの物を隠さないように描いている。
  【場所】  Player.cpp（AddSwordTrailSample・CreateSwordTrailTexture など）

■ ヒットエフェクト（Effekseer）
  ・Effekseer は、エフェクト（光・火花など）を作って再生するツール。
  ・攻撃が当たった位置に、攻撃の種類ごとのエフェクトを、プレイヤーの攻撃の向きで出す。
    クリティカルの時は大きくする。
  ・振るたびではなく当たった時だけ出す（敵がいない時に出ない・軽くなる）。
  ・エフェクトの名前は EffectPlayer.h に1か所でまとめていて、名前を "" にすると出なくなる。

■ オーラ（モード切り替え）
  【仕組み】体を少しだけ大きくしたものを、「裏側だけ」光の色で重ねて描く。
            表を描かずに裏だけ描くと、体のふちだけが光って見える（輪郭線を描く方法の応用）。
  【理由】  エフェクトのファイルを作らなくても、モードが切り替わったことが分かるようにするため。


============================================================
 10. 敵の動き
============================================================

■ 敵のステート
  ・待機 → 気づいたら追いかける → 近づいたら殴る、の繰り返し。
  ・殴る時は、振りかぶっている間だけプレイヤーの方へ向きを変え続ける。

■ 飛びかかり攻撃（GroundSmash）
  【何か】  少し離れたプレイヤーへ、飛び上がって放物線で飛び、着地で周りを叩きつける。
  【仕組み】
    ① 構え（24フレーム）：しゃがんで力をためる（回避・ガードの合図）。
    ② 飛ぶ：その時のプレイヤーの位置へ、重力から計算した放物線で飛ぶ。
            上がる時間にちょうど終わるよう、飛び上がるアニメーションの速さを合わせる。
    ③ 着地：着地予測で、着地の瞬間にアニメーションの「足が着くフレーム」になるよう合わせ、
            「両手を叩きつけるフレーム」で周りを丸く攻撃する。
    ④ すき：起き上がるまで動かない（反撃のチャンス）。
  【工夫】  アニメーションを Python で解析して、足が着くのは6フレーム目、
            叩きつけは10フレーム目、と数値で調べてから合わせた。
  ・飛びかかりの途中は殴られてものけぞらない（スーパーアーマー）。


============================================================
 11. 画面の表示（UI）
============================================================

  ・HP・ATB・ガードのゲージ、技の枠（使えるか・CT・使う本数）、モードの表示。
  ・画像を使わず、四角形（DrawBox）と三角形・円をプログラムで描いている。
    【理由】色や長さを自由に変えられ、光らせる演出もしやすい。
  ・同じ形のゲージは、1つの関数（DrawGaugeBar）で描くようにまとめた。
  ・文字は UIText（KdFont）で描く。タイトルのロゴは Y224 というフォントを読み込んで使う。


============================================================
 12. タイトル画面
============================================================

  【何か】  ゲームと同じステージで、キャラが技を見せ続け、
            その上にロゴ・メニュー・火の粉を重ねた、いつも何かが動いている画面。
  【部品】  TitleChara（技を見せるキャラ）・TitleCamera（ゆっくり動くカメラ）・
            TitleEmber（火の粉）・TitleUI（ロゴ・メニュー）。地面・空・廃墟はゲームと同じもの。

■ キャラが技を見せ続ける（TitleChara）
  ・「台本」の順番にアニメーションを再生する。
    構え（2.5秒）→ 攻撃1の4連撃 → 構え → 攻撃3の4連撃 → 構え → 攻撃5の4連撃 → 最初に戻る
  ・連撃は途中（25フレーム目）で次の段に移るので、途切れずにつながって見える。
  ・振り始め（10フレーム目）に、ゲームと同じ斬撃エフェクトを出す。

■ カメラがゆっくり動き続ける（TitleCamera）
  ・最初の3秒は、遠く・高い所からキャラに寄ってくる。
  ・その後は、キャラの周りを左右・前後・上下にゆらゆら動き続ける。
    ゆらゆらの正体は sin（サイン）。「-1 → 0 → +1 → 0 → -1 …」と行ったり来たりする数を、
    回り込む角度・距離・高さの3つに使い、3つの速さをバラバラにしているので、
    同じ動きの繰り返しに見えにくい。
  ・カメラはキャラの少し左を見ているので、キャラが画面の右寄りに映り、
    空いた左側にロゴとメニューを置ける。

■ 火の粉が舞い上がり続ける（TitleEmber）
  ・小さな火の粉 70個 と、大きくぼんやりした光の玉 10個。
  ・1粒ごとに位置・速さ・大きさ・寿命をランダムに決め、毎フレーム少し上へ動かし、
    左右にゆらゆらさせる。寿命が来たら画面の下から出し直すので、ずっと途切れない。
  ・生まれる時と消える時は1秒かけて明るさを変えるので、パッと出たり消えたりしない。
  ・加算合成で描いている（光の表現向き）。

■ ロゴとメニュー（TitleUI）
  ・最初の約3秒で順番に現れる：黒い画面から明るくなる → ロゴ「BRAVER」が縮みながら現れて
    キラッと光る → ロゴの下に光の線が伸びる → メニューが左から滑り込む。
    （Enter・クリックで飛ばせる）
  ・その後も、ロゴの後ろの光が呼吸するように明るさを変え、線の上を時々光が走る。
  ・メニュー：START（ゲームへ）・CONTROLS（操作説明）・EXIT（終了）。
    W / S（↑ / ↓）で選び、Enter / Space で決定。マウスを乗せると選ばれ、クリックで決定。
  ・画面の四隅を少し暗くし、上下に黒い帯を入れて、映画のような雰囲気にしている。

■ よく使っている考え方
  ・進み具合（0 → 1）：「〇フレーム目から△フレームかけて 0 → 1 になる数」を作り、
    透明度や大きさに使う（だんだん見えてくる・だんだん大きくなる）。
  ・スッと動いて、ふわっと止まる：最初は速く、最後はゆっくりになるよう変換してから使う。
  ・目標に少しずつ近づける：毎フレーム「目標までの残りの20%」だけ動かす。
    遠いうちは速く、近づくとゆっくりになり、なめらかに止まる（カーソルの移動など）。

 13. FPS（フレームレート）の制御
============================================================

  【問題】  いつも 58～59 FPS になっていた。
  【原因】  Sleep（待つ命令）は 1ミリ秒単位で、しかも少し長めに待つため、
            1フレームが約17ミリ秒（＝約58.8 FPS）になっていた。
  【仕組み】細かい時間を測れるタイマー（QueryPerformanceCounter）で、
            「次のフレームを始める予定の時刻」まで待つようにした。
            大きく遅れた時は、今を基準にし直す（遅れを取り戻そうとして早送りしないように）。
  【場所】  Src/Framework/Utility/KdFPSController

 15. 用語集（聞かれやすい言葉）
============================================================

  ステート        ：「待機」「攻撃」など、キャラの今の状態。状態ごとに処理を分ける。
  ブレンド        ：2つのアニメーションを少しずつ混ぜて、なめらかに切り替えること。
  リターゲット    ：別の体型用のアニメーションを、別のキャラに合わせて作り直すこと。
  ルートモーション：アニメーションの動きどおりにキャラを移動させること。
  OBB             ：向きを持った箱の当たり判定。剣のような細長い物に向いている。
  主成分分析      ：点の集まりが、どの向きに一番広がっているかを求める計算。
  ヒットストップ  ：攻撃が当たった瞬間に一瞬止めて、手ごたえを出す演出。
  先行入力        ：少し早く押したボタンを覚えておいて、動けるようになった瞬間に使うこと。
  キャンセル      ：動きの途中で、次の行動に切り替えること。
  CT（クールタイム）：技を使った後、もう一度使えるようになるまでの待ち時間。
  加算合成        ：色を足し算して重ねる描き方。光の表現に向いている。
  Catmull-Rom 曲線：点と点の間を、なめらかな曲線でつなぐ計算方法。
  glTF            ：3Dモデルやアニメーションを保存するファイルの形式。
  フレーム        ：画面を1回描きかえる単位。このゲームは 1秒 = 60フレーム。

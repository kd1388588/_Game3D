------------------------------------------------------------
1. 全体の流れ（1フレームの処理順）
------------------------------------------------------------

  Player::Update()
    ├ m_isTrailAddedThisFrame = false          … 「今フレーム追加したか」をリセット
    ├ ステートの更新（PlayerStateComboAttack::Update）
    │    └ 攻撃判定のフレーム中（10～45F）だけ
    │       player->AddSwordTrailPoints() を呼ぶ   … 左右の剣の位置を軌跡に追加
    └ UpdateSwordTrails()
         └ 今フレーム追加していなければ、軌跡を古い方から少しずつ消す

  Player::DrawEffect()
    └ 左右の軌跡ポリゴンを、加算合成・深度書き込みなし・カリングなしで描画


------------------------------------------------------------
2. 軌跡の「形」の作り方
------------------------------------------------------------

■ KdTrailPolygon の仕組み
  ・AddPoint(行列) で行列を1つずつ登録すると、登録した行列を順につないだ
    帯状のポリゴンを作る。
  ・各行列について「平行移動の位置」を中心に、「X軸（Right）の方向」へ
    帯の幅を広げる。帯の幅は「X軸の長さ × 0.5」になる。
  ・SetLength(数) を超えると古い行列から消えていく。

■ 刃の根元～先端を帯にする（Player::CreateTrailMatrix）
  ・剣の行列(m_swordWorldR / L)から、刃の根元と先端のワールド座標を求める。
      根元 = 剣のローカル座標 (0, kSwordBladeBaseY, 0)
      先端 = 剣のローカル座標 (0, kSwordBladeTipY,  0)
    ※ 刃は剣のローカルY軸方向に伸びている（攻撃判定の赤い箱と同じ範囲）
  ・軌跡用の行列を次のように作る。
      X軸（Right）     = (先端 - 根元) × 2   … 幅が「刃の長さ」になるよう2倍
      平行移動          = (根元 + 先端) ÷ 2   … 刃の中心
  ・これで「刃の根元から先端まで」の幅の帯が、剣の動いた跡に沿って伸びる。

■ なめらかな円弧にする（Player::AddSwordTrailSample）
  ・剣は1フレームで大きく動くので、フレームごとの位置を直線でつなぐと
    多角形（カクカク）になる。
  ・そこで、前フレームと今フレームの間を Catmull-Rom 曲線で補間し、
    1フレームあたり kSwordTrailSubdivision 個（6個）の点を追加している。
  ・Catmull-Rom 曲線は4点（p0, p1, p2, p3）から p1～p2 の間を通る曲線を作る。
      p0 = 前々フレームの位置（無ければ前フレーム）
      p1 = 前フレームの位置
      p2 = 今フレームの位置
      p3 = この先の予測位置（p2 + (p2 - p1)）
  ・刃の根元と先端を別々に補間し、補間した2点から軌跡用の行列を作って追加する。
  ・補間に使うため、直近2フレーム分の根元・先端の位置を
    SwordTrail::baseHistory / tipHistory に覚えている。

■ 軌跡の出し始めと消え方
  ・新しい振りの始まり（前フレームは追加していなかった）では、
    前の振りの軌跡とつながらないように軌跡を全部消してから追加する。
  ・攻撃していないフレームは、古い方から1フレーム分（6個）ずつ消すので、
    振り終わった軌跡が後ろから縮むように消えていく。


------------------------------------------------------------
3. 軌跡の「見た目」の作り方
------------------------------------------------------------

■ テクスチャをプログラムで作る（Player::CreateSwordTrailTexture）
  ・画像ファイルは使わず、起動時に 64×256 のテクスチャを計算で作っている。
  ・テクスチャの向き
      横（U）：0 = 刃の先端側 → 1 = 刃の根元側
      縦（V）：0 = 一番新しい位置（剣のすぐ後ろ） → 1 = 一番古い位置
  ・各ピクセルの明るさ
      ・先端ほど明るく、根元ほど暗い（根元は kSwordTrailBaseBrightness）
      ・古い位置ほど暗い（(1 - V) の1.5乗）
      ・帯の両端と剣のすぐ後ろは、ふちを少しぼかす（smoothstep）
      ・先端付近の新しい部分は白っぽい「芯」の色にする
  ・色は kSwordTrailColor（水色）と kSwordTrailCoreColor（白）を混ぜて決める。

■ なぜ「透明度」ではなく「明るさ」でフェードさせているのか
  ・UnLitシェーダー（KdStandardShader_PS_UnLit.hlsl）には
    「アルファ値が 0.55 未満のピクセルは描かない（discard）」という処理がある。
  ・半透明でぼかした画像を使うと、薄い部分が全部消えて
    中央の細い線や破線しか残らない（以前の見た目の原因）。
  ・そこで、アルファは常に1にして「色の明るさ」で薄さを表し、
    加算合成（KdBlendState::Add）で描いている。
    加算合成では黒（暗い）部分は何も足されない＝透明に見える。

■ 描画の設定（Player::DrawEffect）
  ・DrawEffect は、キャラクターや地面などを描き終わった後に呼ばれる。
  ・ラスタライザ：CullNone      … 帯を裏側から見ても表示される
  ・ブレンド    ：Add           … 加算合成（上の説明）
  ・深度        ：ZWriteDisable … 帯の暗い部分が後ろの物を隠さない


------------------------------------------------------------
4. 調整できる値（Player.cpp 冒頭の定数）
------------------------------------------------------------

  kSwordBladeBaseY / kSwordBladeTipY
      刃の根元・先端の位置（剣のローカルY軸）。攻撃判定の箱もこの範囲。
  kSwordTrailWidthRate      帯の幅の倍率（1.0 で刃の根元から先端まで）
  kSwordTrailLength         軌跡を残すフレーム数（長さ）
  kSwordTrailSubdivision    1フレームの分割数（多いほどなめらか・重くなる）
  kSwordTrailColor          軌跡の色
  kSwordTrailCoreColor      刃先付近の芯の色
  kSwordTrailBaseBrightness 刃の根元側の明るさ（先端を 1.0 とした割合）
  kSwordTrailTexWidth / kSwordTrailTexHeight  生成するテクスチャの大きさ


------------------------------------------------------------
5. 画像ファイルで描きたくなった場合
------------------------------------------------------------

  ・Player::Init() の CreateSwordTrailTexture() の代わりに、
    polygon->SetMaterial("画像のパス") で画像を設定すればよい。
  ・加算合成で描いているので、画像は「黒い背景に光る軌跡」の形で作る
    （黒い部分が透明になる）。アルファは全面 1（不透明）にしておくこと。
  ・画像の向きは上の「テクスチャの向き」に合わせる。

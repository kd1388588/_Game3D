============================================================
 影がアニメーションする仕組み ／ Effekseer のエフェクトの仕組み
============================================================


############################################################
 第1部　影がアニメーションに合わせて動く仕組み
############################################################

------------------------------------------------------------
 1. 影の作り方（シャドウマップ）
------------------------------------------------------------

  影は「シャドウマップ」という方法で作っている。毎フレーム、次の2回に分けて描く。

  ① 光から見た「深さの絵」を作る（BaseScene::PreDraw）
     ・太陽（平行光）の位置にカメラを置いたつもりで、キャラやステージを描く。
     ・色ではなく「光からどれだけ遠いか（深さ）」だけを、1024×1024 の絵に書き込む。
     ・各オブジェクトの GenerateDepthMapFromLight() がここで呼ばれる。

  ② 画面を描く時に、その絵と比べる（KdStandardShader_PS_Lit.hlsl）
     ・画面の1ピクセルごとに「このピクセルは、光から見てどれだけ遠いか」を計算する。
     ・①の絵に書いてある深さより遠ければ、手前に何かがある＝光がさえぎられている＝影。
     ・まわりの数ピクセルも調べて平均するので、影のふちが少しぼける（PCF）。

------------------------------------------------------------
 2. 影がアニメーションしなかった原因
------------------------------------------------------------

  キャラのアニメーションは「スキニング」で動いている。
    ・モデルの頂点は、それぞれ「どの骨に、どれだけ引っぱられるか（最大4本）」を持っている。
    ・毎フレーム、アニメーションで動いた骨の行列を GPU に送り、
      頂点シェーダーで「骨の行列 × 影響度」を足し合わせて、頂点を動かす。

  ところが、①の「光から見た深さの絵」を作る頂点シェーダー
  （KdStandardShader_VS_GenDepthMapFromLight.hlsl）には、このスキニングの計算が入っていなかった。
    → 影だけ、骨を動かす前の最初の姿勢（T ポーズなど）のまま描かれていた。
    → 画面のキャラは動いているのに、影は止まったままだった。

------------------------------------------------------------
 3. 直したこと
------------------------------------------------------------

  ■ 影用の頂点シェーダーに、画面用（VS_Lit）と同じスキニングの処理を入れた

    VSOutputGenShadow main(
        float4 pos        : POSITION,
        ...
        uint4  skinIndex  : SKININDEX,    // ← 追加：どの骨か（4本）
        float4 skinWeight : SKINWEIGHT )  // ← 追加：その骨の影響度
    {
        if (g_IsSkinMeshObj)                       // スキンメッシュ（骨で動くモデル）の時だけ
        {
            row_major float4x4 mBones = 0;
            for (int i = 0; i < 4; i++)
            {
                mBones += g_mBones[skinIndex[i]] * skinWeight[i];   // 4本の骨の行列を、影響度で混ぜる
            }
            pos = mul(pos, mBones);                // 頂点を骨に合わせて動かす
        }
        Out.Pos = mul(pos, g_mWorld);              // ワールド座標へ
        Out.Pos = mul(Out.Pos, g_DL_mLightVP);     // 光から見た座標へ
        ...
    }

    ・骨の行列（g_mBones）は、DrawModel が画面を描く時と同じように GPU に送ってくれるので、
      シェーダー側に計算を足すだけで、アニメーション中の姿勢の影になった。

  ■ プレイヤー・敵・タイトルのキャラの GenerateDepthMapFromLight() で、
    画面を描く時と同じモデル（アニメーション中の KdModelWork）を描くようにした
    （プレイヤーは2本の剣も描くので、剣の影も出る）。

  ■ .hlsl は、ビルドの時に FxCompile で .shaderInc に変換されて、プログラムに組み込まれる。
    なので、シェーダーを直したら、ビルドし直すだけで反映される。

------------------------------------------------------------
 4. 影をきれいに見せる工夫
------------------------------------------------------------

  ・影を作る範囲（30m × 30m）の中心を、カメラではなくプレイヤーにしている
    （StageEnvironment::SetShadowCenter / KdShaderManager::WriteCBShadowArea）。
    → 範囲を広げすぎずに済むので影がぼやけにくく、プレイヤーの影がいつも範囲に入る。
  ・光の向き・強さは StageEnvironment.h にまとめ、タイトルとゲームで同じにしている。

------------------------------------------------------------
 5. 一言で説明するなら
------------------------------------------------------------

  「影は、光から見た深さの絵（シャドウマップ）で作っています。
    最初は影だけ止まっていたので、影を作るシェーダーにも、体を描く時と同じスキニング
    （骨の行列で頂点を動かす計算）を入れて、アニメーションに合わせて影も動くようにしました。」


############################################################
 第2部　Effekseer のエフェクトの仕組み
############################################################

------------------------------------------------------------
 1. 全体の流れ
------------------------------------------------------------

  [作る]  Effekseer エディタ（.efkproj）→ 保存して .efkefc にする → Asset/Data/Effect/ に置く
  [出す]  ゲームのコードで EffectPlayer::Play("ファイル名", 位置 など) を呼ぶ
  [動かす・描く]  KdEffekseerManager が毎フレーム更新して、3D の絵を描き終わった後に描く

  部品は3段になっている。

    | 部品                  | 役目                                                          |
    |-----------------------|---------------------------------------------------------------|
    | Effekseer（ライブラリ）| エフェクトのデータを読み、粒や輪を動かして描く本体           |
    | KdEffekseerManager    | 学校のフレームワーク。Effekseer を DirectX11 で使えるようにする|
    | EffectPlayer（自作）  | ゲームから使いやすくするための窓口（名前・向き・安全チェック）|

------------------------------------------------------------
 2. KdEffekseerManager（フレームワーク側）
------------------------------------------------------------

  ■ 起動時（Create）
    ・DirectX11 用のレンダラー（描く係）とマネージャー（管理係）を作る（粒は最大 8000 個）。
    ・座標系を左手系（LH）にする（ゲームの DirectX と同じ。+Z が奥）。
    ・板（スプライト）・帯（リボン）・輪（リング）・軌跡・3D モデルを描く機能と、
      テクスチャ・モデルを読む機能を設定する。

  ■ 再生（Play）
    ・ファイル名でエフェクトのデータを探し、まだ読んでいなければ読み込んで覚えておく
      （同じエフェクトを何度出しても、読み込みは最初の1回だけ）。
    ・位置・大きさ・速さを決めて再生し、KdEffekseerObject（再生中のエフェクト1つ分）を返す。
    ・KdEffekseerObject で、あとから位置・向き（行列）・色・速さを変えられる。

  ■ 毎フレーム（main.cpp から Update → Draw）
    ・Update：時間を進める。カメラの行列を Effekseer に教える（カメラから見た向きで描くため）。
    ・Draw：3D の物を描いた後に、エフェクトをまとめて描く（光るので、後から重ねる）。

------------------------------------------------------------
 3. EffectPlayer（自分で作った窓口）
------------------------------------------------------------

  Src/Application/GameObject/Effect/EffectPlayer.h / .cpp

  ■ エフェクトの名前を1か所にまとめる（EffectName）
      EffectName::HitPlayer  = "_Claw2.efkefc";     // 敵の攻撃が当たった
      EffectName::Guard      = "_Guard.efkefc";     // ガードした
      ...
    → ファイルを差し替える時は、ここを1行変えるだけ。空 "" にすれば出さない。

  ■ ファイルが無い時は何もしない（Exists）
    ・フレームワークは、無いファイルを読もうとするとデバッグ版で止まる。
    ・先に std::filesystem::exists で調べ、無ければログを出して nullptr を返す。
    ・調べた結果は覚えておく（毎回ディスクを調べない）。
    → エフェクトがまだ用意できていなくても、ゲームは止まらずに動く。

  ■ 出し方の種類
    ・Play(名前, 位置, 大きさ)                … その場所に出す
    ・Play(名前, 行列)                        … 位置・向き・大きさを行列でまとめて決める
                                                 （剣の向きに合わせた斬撃、プレイヤーの前の盾など）
    ・PlayFacingCamera / PlayFacingCameraRotZ … カメラの方を向けて出し、画面の上で回す
         カメラの向き＝ビュー行列の逆行列（X：画面の右、Y：画面の上、Z：奥）を使い、
         「大きさ × Z回転 × カメラの向き × 位置」の行列を作る。
         斬撃のヒットエフェクトを、剣を振った向き（画面の上での角度）に合わせて回すのに使っている。

  ■ タイトルでは出さない（SetEnabled(false)）、シーンを切り替える時は全部止める（StopAll）

------------------------------------------------------------
 4. ゲームの他の仕組みとのつながり
------------------------------------------------------------

  ・色：SetColor で、エフェクトの元の色にかけ算する。
        白く作ったエフェクトに、モードの色（青・オレンジ）や、敵の攻撃の赤をかける。
  ・スローモーション：GameTime::SetScale の中で KdEffekseerManager::SetUpdateSpeed を呼ぶので、
        ATB コマンド中はエフェクトも 10 分の 1 の速さになる。
  ・大きさ：敵の体の大きさ（m_scale）をかけて、ボスとザコで大きさを変える。
  ・出すタイミング：アニメーションのフレームで決める
        （例：敵が振り下ろした手が地面に着く 26 フレーム目に爪のエフェクト）。

------------------------------------------------------------
 5. エフェクトのデータの作り方（このゲームでやったこと）
------------------------------------------------------------

  ・既存のエフェクト（_Sword1-1 / _Claw2 / _boss_death など）は、エディタで大きさ・数・寿命を調整した。
  ・.efkefc の中の編集用データ（EDIT のかたまり）は、zlib で圧縮された XML なので、
    Python で取り出して .efkproj に戻し、数を減らす・短くするなどを自動で直した
    （Tools/AdjustExistingEffects.py）。
  ・新しいエフェクト（モード切り替え・ガード・ガードブレイク）は、.efkproj（XML）を
    Python で組み立てて作った（Tools/MakeEffekseerProjects.py）。盾のテクスチャも Python で作った。
  ・叩きつけ（_GroundSmash）は、Effekseer のサンプル（Gohlem1・foot_smoke1）を組み合わせ、
    地面に沿って広がるように直した（Tools/MakeGroundSmashEffect.py）。
  ・ゲームが読めるのは .efkefc なので、.efkproj は最後にエディタで開いて保存する。

------------------------------------------------------------
 6. 一言で説明するなら
------------------------------------------------------------

  「エフェクトは Effekseer で作り、学校のフレームワークの KdEffekseerManager で再生しています。
    その上に EffectPlayer という窓口を作って、エフェクトの名前を1か所にまとめ、
    ファイルが無くても止まらないようにし、カメラや剣の向きに合わせて回して出せるようにしました。
    スローモーションの時は、エフェクトの再生速度も同じだけ遅くしています。」

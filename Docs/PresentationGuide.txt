============================================================
 1. 剣のトレイル（剣の軌跡）
============================================================

------------------------------------------------------------
■ 一言で
------------------------------------------------------------
  「剣の刃が通った場所を毎フレーム記録して、その跡を光る帯として描いている」

------------------------------------------------------------
■ たとえ話
------------------------------------------------------------
  暗い所で、光る棒を振って写真を撮ると、光の線が残る。
  あれと同じで、「刃の位置」を毎フレームメモしておき、
  メモした場所をつないで帯（リボン）にして描いている。

------------------------------------------------------------
■ 仕組み（4ステップ）
------------------------------------------------------------

【ステップ1】刃の「根元」と「先端」の位置を記録する
  攻撃中、毎フレーム、左右の剣の刃の根元と先端の位置をメモする。

      先端 ●
           |
           |  ← 刃
           |
      根元 ●
           ┃ ← 持ち手

  ※ 刃の長さや向きは、剣のモデルの形から自動で計算している（7章で説明）。

【ステップ2】記録した位置をつないで帯にする
  フレームごとの「根元〜先端」を横に並べて、間を三角形で埋めると帯になる。

      古い ←―――――――――――――――→ 新しい（今の剣）
      先端 ●───●───●───●───●
           │ ／│ ／│ ／│ ／│
      根元 ●───●───●───●───●

  帯を作る部分はフレームワークの「KdTrailPolygon」を使っている。
  記録は15フレーム分だけ残し、それより古いものは自動で消える。

【ステップ3】フレームの間を曲線でつないで、きれいな円にする
  剣は1フレームでかなり大きく動くので、そのままつなぐとカクカクの多角形になる。

      そのままつなぐ　　　　　　曲線で補間する
          ●―――●　　　　　　　　　●･･･●
         ／　　　＼　　　　　　　 ･　　　 ･
        ●　　　　　●　　　→　　 ●　　　　 ●
                                （間に点を足してなめらかに）

  前のフレームと今のフレームの間に、
  「Catmull-Rom（キャットマル・ロム）曲線」で計算した点を6個ずつ足している。

  Catmull-Rom 曲線とは：
    4つの点（2つ前・1つ前・今・この先の予想）から、
    「この辺を通るはず」というなめらかな曲線を作る計算。
    ・2つ前、1つ前の位置は、少しだけ覚えておく
    ・「この先の予想」は、今の位置＋（今 − 1つ前）で求める

【ステップ4】光って見えるように描く
  ・帯に貼る絵（64×256ピクセル）は、Python のスクリプト（Tools/MakeTrailTexture.py）で作った
      - 刃の先端側ほど明るく、根元側ほど暗い
      - 新しい所ほど明るく、古い所ほど暗い（だんだん消えていく）
      - 先端の新しい所は白い「芯」にする
      - オペレーター用（青）とパニッシャー用（オレンジ）の2枚。モードを切り替えると絵を差し替える
      - 画像が無い時は、同じ絵をプログラムで作る（予備の方法）
  ・「加算合成」で描く：色を足し算する描き方。重なるほど明るくなり、光に見える。
    黒い所は足しても変わらないので、透明に見える。

  攻撃が終わったら、古い方から少しずつ消す → 後ろから縮むように消えていく。
  次の振りが始まったら、前の振りの帯とつながらないように一度全部消す。

------------------------------------------------------------
■ 攻撃に合わせて「いつ出すか」を決めている
------------------------------------------------------------
  普通の攻撃は、攻撃判定と同じフレームの間だけ出す。
  ただし、長い技はアニメーションを調べて、ちょうど合うようにした（6章）。
    ・04の溜め攻撃（4-3）：振り始め（2フレーム目）から、回転を通して、剣を地面に突き刺すまで
    ・04の4段目（跳び上がって叩きつける）：剣を抜くところから、落ちてきて地面に叩きつけるまで

------------------------------------------------------------
■ 工夫した点（発表で一番言いたい所）
------------------------------------------------------------
  1. 刃全体から出す
     → 刃の「根元」と「先端」の2点を記録して、その間を帯の幅にした。
        最初は刃の真ん中から細い線しか出ていなかった。
  2. きれいな円を描く
     → Catmull-Rom 曲線で、フレームの間をなめらかに補間した。
  3. 光って見える
     → 半透明ではなく加算合成にした。
        このフレームワークの3D描画は「透明度55%未満の所は描かない」作りなので、
        半透明でぼかすと薄い所が全部消えてしまう。
        そこで「透明度」ではなく「明るさ」で薄さを表した。
  4. 技の最後まで途切れない
     → アニメーションを数値で調べて、叩きつけの瞬間まで出るようにした。

------------------------------------------------------------
■ 台本例（約1分）
------------------------------------------------------------
  「剣を振った時の光の軌跡です。
   剣の刃の根元と先端の位置を毎フレーム記録して、それをつないだ帯を描いています。
   ただつなぐだけだと、剣が速く動くのでカクカクになってしまうため、
   Catmull-Rom曲線という計算で、フレームの間に点を足して、なめらかな円にしました。
   また、光っているように見せるために、色を足し算する加算合成で描いています。
   帯の色はモードに合わせて、青とオレンジで切り替えています。」

------------------------------------------------------------
■ 想定質問と答え
------------------------------------------------------------
  Q. 帯の絵はどうやって作ったのですか？
  A. Python のスクリプトで、明るさを計算して作りました。
     先端ほど明るい・古いほど暗い、などを数値で調整したかったからです。

  Q. 何フレーム分残していますか？
  A. 15フレーム分です。1フレームの間に6個の点を足しているので、帯は最大90個の点でできています。

  Q. 加算合成って何ですか？
  A. 描く色を、下にある色に足し算する描き方です。重なるほど明るくなるので、光や炎の表現に使われます。

  Q. 処理は重くないですか？
  A. 剣1本あたり最大90個の点なので軽いです。攻撃中だけ点を追加しています。

 2. タイトル画面の技術
============================================================

------------------------------------------------------------
■ 一言で
------------------------------------------------------------
  「ゲームと同じステージでキャラが技を見せ続け、その上に、
   時間に合わせて動く文字や光を重ねて、常に何かが動いている画面にした」

------------------------------------------------------------
■ 画面を作っている部品
------------------------------------------------------------
    ┌──────────────────────────────┐
    │　　　　　　　　　　　　　　　　　　　　　　　　　　 │ ← TitleUI
    │　 BRAVER（ロゴ）　　　　　　　　　 ･ 　　　　　　　 │
    │　 ───光の線───　　　　　　･　 　 人 ← TitleChara│
    │　 START　　　　　 ･ 火の粉 ･　　　　　 （技を見せる）│
    │ ･ CONTROLS ･　　　　 ･　　　　　　　 　　　　　　　 │
    │　 EXIT　　　　　 ･　　　　　　　　　 　　　　　　　 │
    │　　　　　　　　　　　　　　　　　　　　　　　　　　 │
    └──────────────────────────────┘
      ＋ カメラ（TitleCamera）がゆっくり動き続ける
      ＋ 背景はゲームと同じステージ（光・フォグ・影も同じ）

    TitleChara  … キャラが「構え→4連撃」を、攻撃の種類を変えながら繰り返す（剣のトレイル付き）
    TitleCamera … 最初に遠くから寄ってきて、その後ゆらゆら動き続ける
    TitleEmber  … 火の粉と光の玉が下から舞い上がり続ける
    TitleUI     … ロゴ・メニュー・操作説明・フェード（上下の黒帯は、画面を広く見せるためにやめた）
    ※ タイトルでは、うるさくならないように Effekseer のエフェクトを止めている

------------------------------------------------------------
■ 技術ポイント（6つ）
------------------------------------------------------------

【1】sin（サイン）で「ゆらゆら」動かす
  sin は「-1 → 0 → +1 → 0 → -1 …」と行ったり来たりする値。
  これを位置や明るさに使うと、ずっと揺れ続ける動きになる。

      +1 │  ／＼　　　　 ／＼
       0 │／　　＼　　　／　　＼
      -1 │　　　　＼／　　　　　＼／
         └──────────────→ 時間

  使っている所：カメラの揺れ・ロゴの光の脈打ち・火の粉の左右の揺れ
  工夫：カメラの「角度」「距離」「高さ」の揺れる速さをわざとバラバラにした。
        → 組み合わせがなかなか同じにならず、同じ動きの繰り返しに見えにくい。

【2】イージングで「スッと動いてふわっと止まる」
  そのまま一定の速さで動かすと、機械的に見える。
  「最初は速く、最後はゆっくり」に変換してから使う（EaseOutCubic）。

      一定の速さ　　　　　　イージング
      位置│　　　／　　　　 位置│　 ＿＿＿
          │　　／　　　　　　　 │ ／
          │　／　　　　　　　　 │／
          └───時間　　　　　　└───時間

  使っている所：カメラが寄ってくる・ロゴが縮みながら出る・メニューが滑り込む

【3】時間に合わせて順番に出す（タイムライン）
  「何フレーム目から何フレームかけて出すか」を決めて、順番に演出する。

      0.0秒～ 黒い画面から明るくなる
      0.5秒～ ロゴが大きい状態から縮みながら現れる
      1.3秒～ ロゴの下に光の線が伸びる
      1.5秒　 ロゴがキラッと光る
      2.3秒～ メニューが左から滑り込む
      3.0秒～ 選べるようになる（Enter で演出を飛ばせる）

  仕組み：「開始フレームで0、終了フレームで1」になる数（進み具合）を作り、
          透明度や大きさに掛ける。

【4】目標に少しずつ近づける（カーソルの動き）
  毎フレーム「目標までの残りの20%」だけ動かす。
  遠いうちは速く、近づくとゆっくりになって、なめらかに止まる。

      距離 100 → 80 → 64 → 51 → 41 → … → ほぼ0

  使っている所：選んだ項目へ動くカーソルの光・項目の大きさ・操作説明の開閉
  工夫：選んだ項目の左右の光の点は、どの項目でも同じ幅にそろえ、カーソルが動いている間は消す。
        （文字の長さで幅が変わると、光だけが先に横へ動いて見えてしまうため）

【5】パーティクル（火の粉）
  ・火の粉70個・光の玉10個を、それぞれ「位置・速さ・大きさ・寿命」をランダムで作る
  ・毎フレーム少し上に動かし、寿命が来たら画面の下から出し直す（使い回し）
  ・生まれる時と消える時は1秒かけて明るさを変える（パッと出たり消えたりしない）
  工夫：消して新しく作るのではなく、同じ粒を使い回している → 無駄な処理が無い

【6】画像を使わず、プログラムで光を作る
  ・光の玉の絵：中心ほど明るく、ふちに向かって暗くなる絵を、1ピクセルずつ計算して作る
  ・画面の四隅を暗くする絵（ビネット）：真ん中に目が行くようにする
  ・光る物は加算合成で描く（剣のトレイルと同じ考え方）

------------------------------------------------------------
■ その他の工夫
------------------------------------------------------------
  ・メニューは「状態」で管理（登場中・選択中・操作説明中・決定後）
     → 状態ごとに受け付ける入力を変えている（例：登場中は Enter で演出を飛ばす）
  ・タイトルロゴは用意したフォント（Y224）をゲームと一緒に配って読み込んでいる
     → どの PC でも同じ見た目になる
  ・文字の中央揃えがずれる不具合を見つけて、フレームワーク側を直した
     （同じ文字が2回目以降に出てくると、その文字の幅が数えられていなかった）
  ・GAME CLEAR / GAME OVER の見出しは、あらかじめ画像にして表示している
     → Windows の文字の描き方（GDI）だと、このフォントの「M」が欠けてしまうため。
        同じフォントを Python（Pillow）で画像にした。

------------------------------------------------------------
■ 台本例（約1分）
------------------------------------------------------------
  「タイトル画面は、常に何かが動いている画面を目指しました。
   背景ではゲームと同じキャラが技を見せ続けていて、カメラもゆっくり動き続けています。
   カメラの揺れはsinを使っていて、角度・距離・高さの揺れる速さをバラバラにすることで、
   同じ動きの繰り返しに見えないようにしました。
   ロゴやメニューは、時間に合わせて順番に現れるようにして、
   イージングで最初は速く最後はゆっくりになる、自然な動きにしています。
   火の粉はパーティクルで、粒を使い回して舞い上がり続けるようにしています。」

------------------------------------------------------------
■ 想定質問と答え
------------------------------------------------------------
  Q. なぜタイトル画面に力を入れたのですか？
  A. 最初に見る画面なので、文字だけだと試作品のように見えてしまうからです。

  Q. 火の粉は何個ありますか？重くないですか？
  A. 小さい火の粉が70個、大きな光の玉が10個です。使い回しているので軽いです。

  Q. イージングって何ですか？
  A. 動きの速さを変化させることです。最初は速く、最後はゆっくりにすると、自然に止まって見えます。

  Q. キャラの技は動画ですか？
  A. いいえ、ゲームと同じモデルとアニメーションを、リアルタイムで動かしています。

 3. 影・光・フォグ・リムライト（見た目をのっぺりさせない）
============================================================

------------------------------------------------------------
■ 一言で
------------------------------------------------------------
  「影を出し、光を斜めから当て、遠くを霧で溶かして、立体感と奥行きを出した」

------------------------------------------------------------
■ 影（シャドウマップ）
------------------------------------------------------------
  仕組み：光の方向から見た「深さの絵（シャドウマップ）」を先に描いておき、
          画面を描く時に「光から見て、何かの後ろにある所」を暗くする。

  困っていたこと：
    キャラの影が、アニメーションせずに最初の姿勢（Tポーズ）のまま動かなかった。
  原因：
    影の絵を描くシェーダー（頂点シェーダー）に、骨に合わせて頂点を動かす処理
    （スキニング）が入っていなかった。
  直し方：
    普通に描くシェーダーにあるスキニングの処理を、影のシェーダーにも入れた。

      頂点の位置 ＝ Σ（骨の行列 × その骨の影響度）× 元の頂点の位置
                    ↑ 1つの頂点は、最大4本の骨の影響を受ける

  工夫：影を作る範囲（30m 四方）の中心を、カメラではなくプレイヤーにした。
        → カメラの位置で範囲が動くと、プレイヤーの影が範囲から外れることがあるため。

------------------------------------------------------------
■ 光とフォグ
------------------------------------------------------------
  ・月明かり（平行光）：斜め横から当てる。真上や真後ろからだと凹凸が見えず、のっぺりする。
  ・環境光：少し暗い青にして、光の当たらない側との差を付ける。
  ・距離フォグ：遠くほど夜の空気の色に溶かして、奥行きを出す。
      見え方 ＝ 1 ÷ e^(距離 × 0.012)  → 20m で約8割、50m で約5割だけ元の色が残る
  ・高さフォグ：地面の近くにうっすら霧。遠くほど濃い（近くのキャラの足元は隠さない）。
  ・空にはフォグをかけない（遠くにあるので、かけると空全体が霧の色になる）。
  ・設定は StageEnvironment.h にまとめ、タイトルとゲームで同じ見た目にしている。

------------------------------------------------------------
■ リムライト（体のふちを光らせる）
------------------------------------------------------------
  仕組み：面の向き（法線）とカメラへの向きの「内積」を取る。
          正面は1、ふち（横を向いた面）は0になるので、1から引くと、ふちほど大きくなる。
          それを pow（累乗）すると、ふちだけが光る。

      光る強さ ＝ (1 − 法線・カメラへの向き) の pow 乗
      pow が小さい → 体全体が光る　／　pow が大きい → ふちだけ細く光る

  使い方：
    ・いつも：体のふちを、今のモードの色（青・オレンジ）で薄く光らせる
    ・モードを切り替えた時：pow を 0 → 10 へ上げて、体全体がパッと光ってから、
      ふちだけになり、いつもの薄い光へなめらかに戻る
  ※ パニッシャーの間は、少しずつ大きくした体を裏側だけ光らせて重ね、
     オレンジのオーラがゆらめくようにしている。

------------------------------------------------------------
■ 台本例（約40秒）
------------------------------------------------------------
  「見た目がのっぺりしないように、影・光・霧を整えました。
   影は、光から見た深さの絵を使う方法です。最初はキャラの影が動かなかったのですが、
   影を描くシェーダーに、骨に合わせて頂点を動かす処理が無いのが原因だったので、追加しました。
   光は斜め横から当てて、遠くは霧で溶かして奥行きを出しています。
   体のふちは、法線とカメラの向きの内積を使ったリムライトで、モードの色に光らせています。」

 4. ステージ（Python で作ったモデル・バリア・見えない壁）
============================================================

------------------------------------------------------------
■ 一言で
------------------------------------------------------------
  「廃墟の道と大聖堂のステージを、Python で形とテクスチャから作った」

------------------------------------------------------------
■ 仕組み
------------------------------------------------------------
  ・Tools/MakeStageModel.py で、箱や柱を組み合わせて形を作り、glTF で書き出す
      石畳の道 → 両側の柱 → 崩れた壁 → 門 → 大聖堂の広間（ボス戦）
  ・石のテクスチャも、ノイズ（ランダムななめらかな模様）を重ねて計算で作った
  ・乱数の「種（シード）」を決めているので、何度作り直しても同じ形になる

------------------------------------------------------------
■ 当たり判定の工夫
------------------------------------------------------------
  ・壁にめり込まない：体の高さの違う所に球を置いて、壁から押し出す。
    速く動いた時は、前のフレームの位置から今の位置へレイ（光線）を飛ばして、
    間に壁があれば手前で止める（すり抜け防止）。
  ・柱のまわりに見えない壁：柱から 0.6m 外側までの見えない箱を、別のモデルとして作り、
    当たり判定だけに使う（描画はしない）。
  ・カメラ：キャラからカメラへレイを飛ばし、壁があればカメラを壁の手前に寄せる。

------------------------------------------------------------
■ ボスの広間のバリア
------------------------------------------------------------
  ・ザコ敵を全員倒すまで、大聖堂の入口を光の膜でふさぐ（通れない）。
  ・倒したら当たり判定を消して、膜を少しずつ消す。
  ・膜の六角形の模様も Python で作った画像。

 5. エフェクト（Effekseer の調整・ヒットエフェクト）
============================================================

------------------------------------------------------------
■ 一言で
------------------------------------------------------------
  「Effekseer のエフェクトを、技や場面に合わせて大きさ・向き・数を調整して出している」

------------------------------------------------------------
■ 工夫
------------------------------------------------------------
  ・斬撃のヒットエフェクトを、剣を振った向きに合わせる
      剣先の今の位置と前のフレームの位置の差から「振った向き」を出し、
      カメラから見た画面の上の角度に直して、エフェクトをその角度に回して出す。
      1ヒットに1本なので、攻撃の回数とエフェクトの数が合う。
  ・攻撃05（剣を投げる技）は、段ごとに専用のヒットエフェクト
      1段目（2連撃）：斬撃1本を振った向きに／2段目（投げた剣が回る）：回転しながら弧を描く斬撃
      3段目（瞬間移動して切り刻む）：4本の斬撃
  ・ガード：体の前に丸い光の盾が出る。ガードを崩されると、盾が赤くなって砕ける。
  ・Effekseer のファイル（.efkefc）の中にある「エディタ用のデータ」を Python で読み出して、
    数を減らしたり、短くしたりした版を作った（敵の撃破・敵の攻撃が大きすぎたので小さくした）。
  ・エフェクトに色をかける機能をフレームワークに足した（モードの色・ダメージの赤など）。


============================================================
 6. アニメーションを数値で調べて合わせる
============================================================

------------------------------------------------------------
■ 一言で
------------------------------------------------------------
  「見た目だけでは分からない時は、アニメーションのファイルを Python で読んで、
   骨の位置を1フレームずつ計算し、数値でタイミングを合わせた」

------------------------------------------------------------
■ やり方
------------------------------------------------------------
  ① アニメーションのファイル（glTF）を Python で読み込む
  ② 1フレームごとに、親の骨から順番に行列をかけて、骨の世界の位置を計算する
  ③ 剣先・足・腰の高さや、動く速さを表にして、「いつ何をしているか」を調べる

------------------------------------------------------------
■ 使った例
------------------------------------------------------------
  ・04の4段目（跳び上がって叩きつける）
      調べた結果：0〜10 剣を抜く、11〜35 跳ぶ（足が約6m）、36〜47 落ちる、48〜49 叩きつける
      → 前は 45 フレームで剣の軌跡も攻撃判定も止まっていて、叩きつけに出ていなかった。
        ゲームの起動時に、同じ計算（剣先が一番高くなった後、地面まで降りてきたフレーム）で
        叩きつけのフレームを求め、そこまで軌跡と攻撃判定を出すようにした。
  ・敵の攻撃
      0〜14 振りかぶり、15〜26 振り下ろし、27〜 手を地面に置いたまま
      → 前は 45 フレームまで攻撃判定が出ていて、振り終わった後に当たっていた。15〜26 に合わせた。
  ・攻撃05 の剣を投げる技
      剣先がどこを、どの速さで飛ぶかを調べて、ヒットエフェクトの出し方を決めた。

------------------------------------------------------------
■ 台本例（約40秒）
------------------------------------------------------------
  「跳び上がって叩きつける技で、剣の軌跡が空中で途切れる問題がありました。
   アニメーションのファイルを Python で読んで、1フレームずつ剣先と足の高さを計算すると、
   叩きつけは49フレーム目なのに、45フレームで軌跡を止めていたことが分かりました。
   そこで、ゲームの起動時に同じ計算で叩きつけのフレームを求めて、そこまで出すようにしました。」


============================================================
 7. その他の技術（短く説明できるように）
============================================================

------------------------------------------------------------
■ ルートモーション（アニメーションの動きどおりに移動する）
------------------------------------------------------------
  一言で：アニメーションで腰が前に進んだ分だけ、キャラ自体を動かす。
  なぜ：　前は、攻撃が切り替わるたびに体が元の位置に戻っていた。
          また、プログラムで動かすと、足の動きと移動の速さが合わず足が滑って見える。
  工夫：　今回の素材は、普通使う「root（足元）の骨」に動きが入っていなかったので、
          「腰の骨」の水平の動きを取り出して使った。上下の動きは使わない。
  見せ方：F4 でデバッグ画面を出し、「Root Motion」のチェックを外すと前の動きになる。

------------------------------------------------------------
■ 剣の当たり判定を、剣のモデルから自動で作る
------------------------------------------------------------
  一言で：剣のモデルの形から、刃の向きと長さを計算して、当たり判定の箱を合わせる。
  なぜ：　モデルを差し替えるたびに、手で位置や角度を調整し直すのが大変だったため。
  仕組み：剣の頂点（形を作る点）が一番長く並んでいる向きを計算する（主成分分析という方法）。
          手から遠い方の端を刃先とする。
  多段ヒット：右と左の剣は別々に当たりを数えるので、二刀流で1振りに2回当たる。
              同じ剣も 10 フレームあければもう一度当たる（回転する技で何度も当たる）。
  見せ方：F4 のデバッグ表示で、攻撃中に出る赤い箱が刃にぴったり重なっている。

------------------------------------------------------------
■ ヒットストップ
------------------------------------------------------------
  一言で：当たった瞬間、プレイヤーも敵も数フレーム止めて、画面を少し揺らす（手ごたえ）。
  数値：　普通 4 フレーム・クリティカル 7 フレーム・重い攻撃（パニッシャー・技）は +2。
  工夫：　当たり判定の関数の中で自動でかけるので、どの攻撃にも同じルールでかかる。

------------------------------------------------------------
■ バトルモードと ATB ゲージ（FF7リメイクを参考）
------------------------------------------------------------
  一言で：E キーで2つのモードを切り替え、ためた ATB ゲージで大技（攻撃04・05）を出す。
          F キーでコマンドを開くと時間が10分の1になり、技を選ぶと最後まで自動で出す。
  モード：オペレーター＝攻撃が速い（×1.2）・威力は低め（×0.6）・当てると ATB がよくたまる（×1.5）。
          パニッシャー＝攻撃は遅め（×0.8）・威力が高い（×1.6）・移動が遅い（×0.6）・受けるダメージが多い（×1.3）・
                        ATB は少しだけたまる（×0.75）。
  たまり方：時間ではたまらない。攻撃を当てる・回避することでたまる（回避1回で 8、約12回で1本）。
          パニッシャーのまま回避できる（そのかわり、攻撃が遅く、受けるダメージが多い）。
  工夫：　モード切り替えには 3 秒のクールタイム、攻撃05の後は 5 秒オペレーターに固定。
          技（メニューの上：05＝ゲージ1本・CT3秒、下：04＝ゲージ2本・CT8秒。威力は普通の攻撃の1.5倍）
          を受けた敵は、のけぞり続ける。
  スロー：ゲーム全体で1つの「時間の速さ」を持ち、アニメーション・重力・エフェクトに掛ける。

------------------------------------------------------------
■ ロックオン（自動）
------------------------------------------------------------
  一言で：10m 以内の一番近い敵に自動でロックオンし、カメラを弱く敵の方へ回す。
  工夫：　外すのは 10.5m より離れた時（境目で付いたり外れたりしないように）。
          攻撃を振り始める時だけ敵の方を向き、振っている途中は向きを変えない。

------------------------------------------------------------
■ 敵の動き
------------------------------------------------------------
  一言で：待機 → 気づいたら追いかける → 近づいたら殴る、をステートで作っている。
  工夫：　攻撃の後は少しすき（ザコ約0.9秒・ボス約0.7秒）を作り、その間も追いかけてくる。
          攻撃中はひるまない（スーパーアーマー）。少し離れていると、跳び上がって叩きつけてくる。
          ボスは広間の奥で待っていて、近づくと動き出す。

------------------------------------------------------------
■ UE5 でのリターゲット
------------------------------------------------------------
  一言で：別の体型用に作られたアニメーションを、自分のキャラの体に合わせて作り直した。
  工夫：　作業を Python スクリプトにして自動化した。
          元と先で剣の骨の名前・作りが違うのを見つけて、専用の対応づけをした。

------------------------------------------------------------
■ デバッグの機能
------------------------------------------------------------
  F4：デバッグ表示（ImGui の調整画面・当たり判定の線）の表示・非表示（最初は出さない）
  F1：ATB 満タン　F2：HP 満タン　F3：敵を出す　F5：HP を 1 にする
  F6：無敵の切り替え　F7：ボス以外の敵を倒して、ボスの手前（広間の中）へ移動
  ゲーム中はマウスカーソルを消す（デバッグ表示中は ImGui を触れるように出す）


============================================================
 8. 用語集（聞かれやすい言葉）
============================================================

  フレーム　　　　：画面を1回描くこと。このゲームは1秒に60フレーム。
  ポリゴン　　　　：3Dの形を作る三角形。帯もポリゴンでできている。
                    （プレイヤーは約11万枚、敵は1体約5万枚）
  テクスチャ　　　：ポリゴンに貼る絵。
  補間　　　　　　：2つの値の間を計算でつなぐこと。
  Catmull-Rom曲線 ：いくつかの点を通る、なめらかな曲線を作る計算方法。
  加算合成　　　　：色を足し算して描く方法。光の表現に使う。
  sin（サイン）　 ：-1〜+1 を行ったり来たりする値。揺れる動きに使う。
  イージング　　　：動きの速さを変化させて、自然な動きにすること。
  パーティクル　　：たくさんの小さな粒で、火の粉や煙などを表現する方法。
  ステート（状態）：「待機」「攻撃」など、キャラや画面の今の状態。状態ごとに処理を分ける。
  ルートモーション：アニメーションの動きどおりにキャラを移動させること。
  リターゲット　　：別の体型用のアニメーションを、別のキャラに合わせて作り直すこと。
  OBB　　　　　　 ：向きを持った箱の当たり判定。剣のような細長い物に向いている。
  シェーダー　　　：GPU で動く、描き方を決める小さなプログラム。
  スキニング　　　：骨の動きに合わせて、モデルの頂点を動かすこと。
  シャドウマップ　：光から見た深さの絵。影を作るのに使う。
  内積　　　　　　：2つの向きがどれだけ同じ向きかを表す値（同じなら1、直角なら0）。
  フォグ　　　　　：遠くや低い所を霧の色に近づけて、奥行きを出す表現。
  レイ　　　　　　：まっすぐ飛ばす線。壁があるかを調べるのに使う。


============================================================
 9. 発表で見せるとよい場面（デモの順番）
============================================================

  1. タイトル画面をしばらく見せる（キャラ・カメラ・火の粉・ロゴの光）
  2. CONTROLS を開いて操作説明を見せる → START
  3. 攻撃を連続で出す → 剣のトレイルを見せる
     E でモードを切り替える → 体が光る・トレイルの色が変わる・パニッシャーのオーラ
  4. 敵に攻撃を当てる → ヒットストップ（一瞬止まって画面が揺れる）・斬撃のヒットエフェクト
  5. ATB をためる → F キーでスロー → 攻撃04（溜めて回転し、跳び上がって叩きつける）
  6. 攻撃05（剣を投げる技）を見せる
  7. 止まって Shift でガード → 光の盾が出る
  8. ザコを全員倒す → 大聖堂のバリアが消える → ボス戦
  9. 影・光・霧（柱の影、遠くが霧に溶けている）を見せる
  10. F4 でデバッグ表示 → 「Root Motion」の ON / OFF、当たり判定の赤い箱

  ※ デバッグ表示（F4）は、説明する時だけ出すとスッキリ見える。
